## 方案概述

两层防线堵"AI 跳流程"的结构性缺口——**软约束进决策现场 + 物理闸门与追责锚**。图例：`◆` = 人决策点（停等），【AI】/【人】= 该步主体：

```
任务开工
   ▼
①开工判定单（DEVELOPMENT.md §4.2 + AGENTS.md 注入，对所有 AI 会话自动生效）
   【AI】呈报：情况分析（探查 + 三条件核对）+ 建议与理由 + "走管线/豁免"路径全呈现
   ◆【人】裁决（停等）——无论 AI 判断结果如何（含"条件不满足"结论），最终路由由人定；
            可推翻 AI 的任一条件判断；响应三态：同意提议 / 否决（含选相反路径）/ 修改
   ├──管线──► 6 文档管线（既有）：requirements → design ◆【人】签认（= R2 批准落盘）
   │            → test-plan → 实施 → verification → self-review ◆【人】签认
   └──豁免──► ◆【人】裁决（对话中即完成；留痕=PR 描述要点（§6 既有义务）+ git 历史）
   ▼ 全程，每个物理动作前
②git 写操作逐条授权（升格为 DEVELOPMENT.md 条文）
   ◆【人】逐条授权：AI 每执行一条即停下汇报，等下一条明确指令再继续
   【效果】AI 无法独自把任何违规产物变成仓库历史；任何越权产物落库必经人批准
           commit/push——批准即审查时机，R10 责任制 + git 历史构成完整追责链
```

（曾设计第三层"变更探测 CI 门禁"，经五形态豁免通道评估后整层否决——完整否决记录见备选表 B，追责优先于机器门禁。）

交付物两件（纯文档变更）：`DEVELOPMENT.md` 条款（AI–人协作流程 / 豁免权 / git 纪律）、`AGENTS.md` AIxCoding 段协议摘要。

### AI–人协作流程（写入 §4.2，AGENTS.md 摘要引用）

**总则**：AI 是参谋，人是指挥。AI 做——探查现状（代码/文档/git 状态）、分析整理情况、给出**建议与理由**；人做——一切分叉口的路由决策。AI 每次停等的呈报统一形态：**情况（分析结果）+ 建议（附理由）+ 选项（可行路径全部呈现）+ 停等**。AI 的任何判断（含三条件核对结论）均为参考输入，人可推翻其中任一项。

**流程主线**（任务生命周期一图走完；②~⑧ 为既有 §4 分工，不变）：

```
①接任务
  【AI】探查现状，呈报【开工判定单】（格式见下）：情况 + 建议 + 理由 + 路径选项
  ◆【人】裁决：选定路径，或推翻 AI 任一判断（响应：同意 / 否决 / 修改）
  ├──免判定清单项 → AI 一行报备后执行（清单见下）
  ├──微改动豁免   → 人裁决（对话中完成；PR 描述写要点=§6 既有义务，不设登记文书）
  └──完整管线     → ②requirements（人审）→ ③design ◆人签认（= R2 批准落盘）
                     → ④test-plan（人确认）→ ⑤实施（人抽查越权）
                     → ⑥verification（人核证据）→ ⑦双AI自审 ◆人签认 → ⑧PR
  实施中遇范围扩大 → 停下，回到 ① 的呈报模式重新申请
※全程物理闸门：git 写操作逐条授权——AI 每执行一条即停下汇报，等下一条指令
```

**环节一：开工判定单**（免判定清单之外的任务必输出；拿不准的任务也输出）：

```
【开工判定单】
任务：<一句话>
情况分析：
  涉及文件 / 预估规模（产品代码 X 行 · 测试 Y 行 · 文档 Z 行）
  豁免三条件核对（DEVELOPMENT.md §6）：
    ① 上游文件触及：<数量；>0 即不满足>
    ② ADR 判定四问：<逐问一句结论>
    ③ 规模：<与预估合计>
建议：<走完整管线（目录 aixcoding/docs/<feature>/）/ 申请豁免 / 清单项匹配> + 理由
选项：走完整管线 / 豁免（两条路径恒呈现，不因核对结论隐藏其一）
停等：请裁决
```

**免判定清单**（封闭，规范预定义；清单内 = 执行性任务，无需裁决）：

- 活文档追加与常规更新：`verification.md` / `plan.md` / `test-plan.md` / `requirements.md`（`design.md` / `adr/` / `self-review.md` 正文修改**排除**，受签认规则约束）；
- 只读操作：读文件、`git status/log/diff/show/fetch`、跑测试验证；
- 已签认方案范围内的实施动作（写码 / 跑测试 / 自检；匹配口径与 §4.2 条文一致：该动作与 design 变更清单 / R2 表逐项对应，对不上即停等）。

清单内任务：AI 一行报备后直接执行——**报备不是请示**：

| | 请示（判定单模式） | 报备（清单内任务模式） |
|---|---|---|
| 动作 | 呈报情况+建议+选项 → 停下等人回复 → 按回复行动 | 一行说明（做什么 + 清单项编号）→ 直接执行 |
| 适用 | 清单外的分叉口任务 | 规范预定义的执行性任务 |
| 人的角色 | 事前决策 | 事后可纠正（不同意随时叫停） |

示例：

```
【报备】追加 #16 F6 目视结果至 verification.md（清单项①：活文档追加）→ 直接执行
【报备】按已签 design 实施 session.py 第 3 处埋点（清单项③：已签方案内实施）→ 直接执行
```

报备的三作用：**归类显式化**（点明清单项编号，归类错误一眼可纠——防"借清单之名越权"）、**留痕**（对话可追溯 AI 的自主动作）、**可打断**（叫停损失为零）。边界：用户明确指令过的任务无需报备（指令即知情，执行汇报属于对指令的响应），报备只用于 **AI 自主发起**的执行动作。**AI 对清单只做机械匹配，不得现场判断"这个任务算不算纯文档"来自行归入**——判断权要么在规范（预定义清单），要么在责任人（现场裁决），唯独不在 AI；拿不准即输出判定单停等。

**豁免的留痕**：豁免决策在开工判定单的对话中由人做出，不设登记文书（签认重量与变更重量成比例——百行级微变更不值得签字文书）；既有义务不变：§6 微改动豁免本就要求 PR 描述写需求与方案要点 + 验证输出，PR 与 git 历史即留痕。

**灰区三问**（即 §6 落盘的"豁免裁决指引"）：将来回滚/升级要独立追溯吗 / 有需对照核验的验收标准吗 / 半年后无背景文档能看懂意图吗——任一"要/有/不能"走管线；纯机械变更（typo/格式/明显单行修复）直接豁免。

### git 写操作纪律（升格为 §4 条文）

- 任何 git 写操作（commit/push/branch/merge/stash 等）逐条授权：**每条执行后停下汇报，等下一条明确指令再继续**；同一回连贯发多条即使整体曾获概括确认亦违规；
- 聊天中的认可一律是讨论性反馈；进入实施的唯一信号是 design.md 签认字段落盘（R2 批准同此，既有条文重申）。

## 风险与最坏情况

- **判定单是软约束、无机器兜底**（探测已否决）：AI 可能不输出判定单直接干活 → 三重缓解：AGENTS.md 自动注入覆盖所有 AI 会话（规范进入每次决策现场）；责任人以"无判定单即违规"为抽查信号；git 授权闸天然二次把关——任何越权产物要进仓库必经人批准 commit/push，批准即审查时机，事后 R10 责任制 + git 历史可追责（决策可追责是自觉遵守的制度基础，责任人 2026-10-29 裁决）；
- **决策错了会怎样**：两层均为文档条文，回滚 = 还原 `AGENTS.md` / `DEVELOPMENT.md` 段落，零工具、零残留。

## ADR 判定

按 §6 checklist 四问：

1. 有被认真考虑但否决的备选方案（B/C/D 三案，见对比表；其中 B 含变更探测豁免通道五形态的完整否决记录）→ **是**；
2. 撤销代价高（判定单协议 + git 授权条文化一旦成为团队工作约定，后续所有批次的开工与 git 交互模式都依赖它，撤销影响流程预期）→ **是**；
3. 约束未来工作模式（所有 AI 与责任人的开工协议、豁免裁决模式、git 交互纪律——后来者会问"为什么每次开工要判定单"）→ **是**；
4. 依赖上游非公开接口或行为 → 否（AGENTS.md 段为 fork 自有）。

→ 判定：**出 ADR**。落点 `aixcoding/docs/standards/adr/0012-两层流程防线与探测否决.md`（**全局池**而非 feature 池：决策约束一切后续批次的开工与 git 交互模式、落点为全局规范（DEVELOPMENT.md / AGENTS.md），不随特性目录消亡——符合 §6 分池判据"全局/架构级"；编号取现有最大 0011 + 1），内容：两层防线的决策快照——豁免权归人的理由（自判自执无制衡）、追责优先于机器门禁的裁决（探测豁免通道五形态否决记录，防重复提议）。
