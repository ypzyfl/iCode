## 方案概述

决策记录双档制：**正式 ADR 档（`standards/adr/` 全局池，语义 ID，既有体系不动）+ `madr/`（日期档，轻量，本批新增）**。核心组合：详证强约束（决定人 + 决定内容必须被 git 可查载体支撑，默认载体 = 本 PR）+ 三层界限机制（事前 AI 档位建议人裁决 / 写时哨兵 / 事后低频审计）+ 负担红线（对人的全部新增动作收敛为 PR review 一条合并核对项 + 低频审计呈报看一眼）。

机制细则单源落 **ADR-decision-log--dual-tier-decision-records** 正文；`DEVELOPMENT.md` 只做最小指向（R8 一句 + §6 两句），不加 R 系列条款——总纲增规则须过修订元规则评估（本批机制为 ADR 附属细则而非普适行为规则，且要防总纲膨胀侵蚀速查）。

### 载体形态

- 位置：`aixcoding/docs/madr/`（工程记录，与 `standards/` 平级——madr 条目是记录不是规范；目录命名与 `standards/adr/` 构成术语对称，双档信号由 `madr↔adr` 承载而非目录层级）；
- 目录名 `madr` 而非 `decisions`：MADR（Markdown Any Decision Records）为业界共识术语，指向明确；`madr` 为独特检索 token（`decisions` 高频普通词，git/rg 搜索噪声大）（责任人 2026-11-12 裁定）；
- 命名：`YYYY-MM-DD-主题.md`——零分配协调、零抢号冲突、文件名字典序即时间序；**落点目录与命名形态即档位信号**（`adr/` 语义 ID = 正式档，`madr/` 日期 = 轻量档），后来者不读规范即可区分
- 模板（每文件 4–5 行，MADR 压缩版）：

```markdown
# <主题>

- 决定人：<拍板者，多人则首位为最终拍板>
- 背景：<为什么需要决策，1 行>
- 决定：<选了什么，1 行>
- 否决项：<为什么不 X，1 行，无则省略>
- 详证：本 PR / PR #NN / <commit> / <仓库文档路径>
```

- append-only：决策内容不回改；改动决策 = 新条目。

### 机制清单（终态，细则落 ADR-decision-log--dual-tier-decision-records）

1. **防腐烂对称论**：漏登 = 仅缺失（回到 PR 承载的现状，永不误导）；滥登 = 记录不存在的决策，与 INDEX.md 失真**同构**（血亏）——故防腐烂论证必须对称，滥登由机制 2/3/4 封堵，不得以"写了就赚"单方向辩护。
2. **详证强约束（否决性条件）**：详证必须指向 **git 可查载体**（PR 描述 / commit / 仓库文档）；纯对话拍板不构成有效详证，须先外化方可落条目——与 R10"不以聊天记录为凭"同构。**时序与默认口径（七/八次修正）**：默认且合法载体 = **本 PR**——豁免区拍板现场即本 PR 的 commit 授权前呈报（决策要点写入本 PR 描述即完成外化）；"本 PR"即自足（条目与 PR 同体，diff 同源，归属经 `git log --follow`/blame 可查，**无回补编号动作**——回补号 = merge 后再改文件，为冗余编号多一次修改，不落地）；决策现场在更早处（旧 PR/commit/批次文档）时指向之。peer review 固定核对项**合并为一条**："madr/ 条目：档位是否恰当（未命中 ADR checklist？）+ 详证载体是否真的支撑决定人与决定内容"。
3. **档位裁定流程（AI 建议人裁决，分场景二元）**：不存在统一的三选一判断，按决策现场分两轴各自二元——**豁免路径微改动中的决策**（随 PR）：豁免资格本身已含"未命中 ADR checklist"（三条件②），档位只剩**落 madr/ 条目 / 不落**（PR 描述承载即可）；AI 起草条目随 PR 提交（**起草 = 建议的实体形式，非决定**——同 design.md"AI 起草、人签认"模式，签认形态在此为 commit 授权前呈报中的明确表态），PR 描述附一行"落条目 + 一句理由"建议；**含条目的 PR，AI 在 commit 授权前的呈报中附条目全文请人表态，人的回复须含明确表态（落/不落）——无表态则 AI 追问、不得默认**（裁决口径按频率定档：三层过滤——豁免区少数/"值得留痕"再滤/重要否决走 ADR——下预期低频，月均个位数，逐条表态负担可控；该回合因 git 写操作逐条授权而必然存在，条目裁决零增量交互）；**纯讨论/否决产生的决策**（R8 场景，无改动载体）：档位二选一**出 ADR / 落 madr/**，对照 checklist——完整管线的决策由 design.md/ADR 承载，madr/ 不涉足（见非目标）；落条目须先外化详证。判定单场景：任务路由建议（完整管线/豁免）为既有内容，如含决策落点问题按上述两轴附建议（搭既有停等便车，零新增独立停等点）。**免判定清单不扩 madr/**：条目落盘本身必经人（merge 或判定单）。
4. **写时哨兵**：起草条目时若发现否决项被**认真权衡过** = 命中 ADR 判定① = 豁免三条件②不成立——这不是档位选择，是**豁免资格失效信号**：停等呈报、退出豁免走完整管线（决策由 design.md 承载，命中 checklist 则出 ADR）；决定涉及上游接触面同理（三条件①失效）。"否决项"字段自带检测语义，写条目的动作本身暴露豁免判定错误。
5. **事后低频审计**：AI 于既有节律点扫描 madr/ 目录，呈报一行结论（该升格的滞留条目、同主题条目堆积、可疑档位），人裁决处置；**呈报含条目频率观测——显著超出低频预期（如持续月均 >5 条）时，建议责任人重估裁决形态**（备选含批量集中裁决：条目攒批一次表态；当下不引入——集中文档写冲突回归、条目时效断裂、两状态搬运三代价）。节律挂点建议：**升级批次启动时**（UPGRADE-RUNBOOK 已有节律，天然同频；备选：按需触发），随签认裁定。
6. **升格通道**：条目事后证明撤销代价高/约束未来 → 出正式 ADR 引用之（按文件名引用）；条目本体不回改，升格信号由 ADR 侧单边引用承载。
7. **R8 落点（场景分流，评审 B1 修正）**："决定不做"按场景分流——完整管线内由 design.md 备选对比承载（madr/ 不涉足）；微改动豁免区可选落 madr/（§6 口径）；纯讨论（无改动载体）是 madr/ 最典型场景，未命中 checklist 落条目、重要否决（认真权衡过备选）命中判定① 走 ADR——log 接的是"没到①但想记一句"的那类否决。
8. **必要性定位（ADR-decision-log--dual-tier-decision-records 论据）**：主论据 = 防 ADR ③稀释（双向：严格执行③的泛滥与软性收窄的选择性忽略）+ R8 落点补齐；**不以"中间地带决策"为主论据**——③字面（后来者会问为什么）已覆盖大部分中间地带，它恰是③松紧执行的灰色出口而非③之外的领地。
9. **负担红线**：无新增独立停等点、无新增走 **R10 签认机制**的文档（签认 = 责任人本人编辑头部签认字段组[责任人/状态/确认日期/确认意见] + check_docs 签认校验的批准门槛，仅 ADR/design/self-review 三类；条目不入此列——**决定人字段是归属事实记录而非签认动作**：AI 按实际拍板事实填写、人 review 校正，条目批准由下方三层链承载，不依赖签认字段组）、无新增 CI 门禁、无新增工具校验（check_docs 零适配）。**条目虽无签认字段组，批准链不缺位（三层）**：① commit 授权前呈报全文、人明确表态"落/不落"（此表态即对条目全文含决定人字段的确认，无表态追问）；② merge 事实——条目随 PR 提交、人 merge 即批准该条目，GitHub 持久可查（同 R13"批准指向 PR"凭据模式：条目批准由 PR 级批准承载，不在每条目旁单独签字）；③ peer review 固定核对项（决定人 + 决定内容被详证支撑）。加签认字段组即成小 ADR（"本人编辑文件"要求与 merge 工作流摩擦），非轻量档形态。工具校验（决定人/详证非空格式检查）只防漏填不防伪造，不作为本批依赖，留作后续增强选项。
10. **C 方案并入（rule of three）**：同类微改动累积（约第三次，含"本次微调重访了之前某次微调结果"）→ 把散在若干 commit 里的演进脉络固化为对应主题既有文档的小节/条目（批次活文档、standards 规范，均属免判定清单①活文档追加）；无对应文档且值得独立追溯 = 命中 §6 既有退出条件，走完整管线；无需独立追溯则继续豁免。log（决策点时间线/临时态）与活文档（主题稳态聚合）构成同一条信息生命周期的两段。
11. **条目非决策性修正口径**：typo、失效链接、格式等不改变决策语义的修正允许原地改（同 ADR"原地修改仅限非决策性修正"口径）。

## 风险与最坏情况

- **滥登伪决策**（评审三否决性风险）：已由详证强约束（git 可查对象）+ 人 merge 裁决 + 写时哨兵三层封堵；残余 = review 略过核对项 → 签认即明示接受（与 ADR-0012"追责优先于机器门禁"同取向）；
- **低频空转没人写**：良性缺失（回到现状不更糟），非失败模式；
- **ADR 弱化漂移**（该出 ADR 出了轻量条目）：哨兵（认真权衡必 ADR）+ 低频审计；反向（轻决策硬出 ADR）由 ADR 签认流程自然把关，不加新机制；
- **负担变形执行**（红线被侵蚀）：红线入 ADR-decision-log--dual-tier-decision-records 正文为验收项；
- 回滚：删 madr/ 目录 + ADR-decision-log--dual-tier-decision-records 标记被取代 + 撤三处联动，零代码影响。

## ADR 判定

1. 被认真考虑但否决的备选？——**是**（B/C/D/E/F 对比，形态与辩护链均为明确取舍）；
2. 撤销代价高？——否（删目录即回滚）；
3. 约束未来工作模式？——**是**（新增决策落点义务与档位裁定流程），该约束即本批目的，决策档随 ADR-decision-log--dual-tier-decision-records；
4. 依赖上游非公开接口或行为？——否。
