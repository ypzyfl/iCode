# 需求：企业埋点迁移

目标版本为 0.35.2（`10ec90ee`），现网对照为 0.28.0（`019d12b1`）。迁移保留 TUI、ACP、headless 和 Workflow 中原已覆盖的企业报文，降低后续升级需要改动的上游范围。

| 编号 | 验收标准 |
| --- | --- |
| T01 | 模型请求保留旧 `body.telemetry` 结构、agent/system 区分和字段缺省。逐种重试对照逻辑请求与 HTTP 尝试的关系。 |
| T02 | 工具 save、PENDING、终态的次数和顺序与旧版对齐。内部 ID 允许变动，但关联关系、状态、失败分类和参数口径须对齐。 |
| T03 | write/edit 的逐次行数、片段、范围、审批状态与旧版对齐。A→B→A 仍保留两次执行。缺失快照按旧规则处理。 |
| T04 | 用户技能引用、模型 `load_skill` 和选定桌面 Agent 保留各自的触发条件。ACP 保留原企业 envelope 与新版 `chrys` 元数据。 |
| T05 | 用户身份、环境端点、渠道、项目和 Git 归属与旧口径对拍。版本号等允许自然变化，差异必须可解释。 |
| T06 | 相同 provider 工具 ID 在并发、重试或多个会话中出现时，不发生错挂。历史恢复、回滚和 fork 不制造新上报。 |
| T07 | 上报故障不破坏正常模型和工具执行。关闭埋点时不发送。能区分已发送、失败和丢弃。 |
| T08 | 在后续引擎基线上验证同一份企业编码器可继续复用，记录实际修改的上游文件、行数和影响。 |

旧实现未覆盖的第三方 ACP 子 Agent 内部调用不纳入等价承诺。新增企业接口、后台协议和统计口径单独裁决。外部上报的字段详见 [design.md §5](design.md#5-旧-wire-契约冻结表)。
