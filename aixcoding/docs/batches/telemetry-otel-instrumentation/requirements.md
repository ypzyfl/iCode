# 需求：官方 iCode 零源码修改的外置业务埋点

## 背景与范围

责任人要求：业务采集与上报代码独立出来，不修改官方 iCode 源文件；接入能力从官方源码分析，已交付实现仅参考企业报文和业务语义。研究目标不是为不改源码而绕道重建 session，而是在执行当下使用 OTel/instrumentation 取得事实。

本轮模拟目标为官方 0.36.0 提交 `78802f87d07f053fe560d680e4696c2bf322e2c2`，0.35.2 提交 `2fd777f626649d53d7ccd701e26a1a7ada569ce8` 为兼容回归目标；未来官方版本通过独立适配器和注册表扩展，不限于这两个版本。本地 fork 同名 tag 不作官方依据。已交付业务参考为 fork `1709f237694b89f74deb4fb8fae47f216fe6c852`；来源与设计详见 design.md。

| RQ2 | 独立包显式装配，所有运行时包装有清单、版本限制、诊断与卸载 | 冷启动、重复安装、冲突、未知版本、回滚 |

## 业务兼容约束

以现有企业模型记录和 tool-detail/ai-code 报文为初始需求：接口、触发、状态、字段缺省、逐次片段/行数和 ID 等值关系都要比较。不得将“改为 OTel”隐式解释为改用 trace_id/span_id、只报成功、改 final-only 或删除时间字段。session 探索的差异仅在责任人明确选择后纳入本批。

实际 load_skill 才计技能使用；已有项目名不取安装目录/进程 cwd 的规则保留。catalog 模型过滤按业务确认范围执行；缺少 model/source 的可证明身份不能猜。工具/代码挂产生它们的模型调用 A1，最终 ACP 通常挂 A2。

本地子 Agent、Workflow、hosted 以已交付覆盖为业务需求输入，各自列验收，不假装全部已通过。远程 ACP Agent 的内部不可见调用不由本地 SDK凭空补采。

## 非目标

- 不实施新功能、不修改官方文件、不安装第三方依赖、不发布或切换生产。
- 不 fork OpenLLMetry，不以全量 SDK 的安装作为交付条件。
- 不做 session 扫描主链、崩溃历史补报或持久化 exactly-once 保证。
- 不默认要求后台改用 OTel 协议，不默认进行历史数据迁移。
- 不将同进程 Python 装配能力外推为任意冻结/独立二进制可注入。
- 不承诺任意未知未来版本无需适配/验证即可自动工作；版本新增只允许改伴随包，不通过修改官方源码补齐。
