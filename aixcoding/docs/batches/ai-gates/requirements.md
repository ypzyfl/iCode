# 需求：AI 流程闸门（ai-gates）

> 活文档：随时更新、不签认（git 留痕）；意图确认由 design 签认承载。

## 背景与问题

2026-10 连续发生 AI 越权事件（PR #67 扫描器行为变更越权、auth-logging 批次跳过文档管线直接准备实施、git"逐条执行"承诺未兑现即连贯执行）。复盘根因不是规范缺失——`DEVELOPMENT.md` §4 铁律、§6 管线、R10 签认均已存在——而是三个结构性缺口：

1. **规范是"知识"，不在决策现场**：`DEVELOPMENT.md` 按需读取，任务中段的 AI 上下文里往往只有"用户最新一句话"，聊天确认的权重压过不在场的铁律；"方案未签，不动代码"没有对应的 AI 行为触发条件定义（什么信号出现才允许实施）。
2. **开工流程判定无协议**：§6 微改动豁免三条件没写判定权归谁，AI 可以自判豁免跳管线（自判自执，无制衡）。
3. **门禁只校验文档格式，不校验变更集**：`check_docs.py` 扫既有文档签认字段，"零文档的定制代码变更"这一最高频违规形态没有任何门禁能拦。
4. **git 写操作授权纪律只在 AI 私有记忆**：换一个无此记忆的 AI 即失效，对团队不可复用。

其中缺口③（无变更集机器门禁）经五形态豁免通道评估后决定不补（2026-10-29 责任人裁决，详见 design.md 备选表 B）——追责机制（开工裁决 + git 授权批准 + R10 + git 历史）是更根本的保障；本批解缺口①②④。

## 目标与非目标

- 目标：
  - 流程分叉口决策权显式归人：AI 第一步输出结构化开工判定单（情况分析 / 建议与理由 / 路径选项），责任人裁决（可推翻 AI 任一判断）；
  - 追责链落盘：开工裁决 + git 授权批准 + R10 签认构成可定位、可追溯的责任链（决策可追责是自觉遵守的制度基础）；
  - git 写操作逐条授权升格为 `DEVELOPMENT.md` 规范条文（对所有 AI 生效，不依赖私有记忆）；
  - 关键 AI 行为协议摘要进入 `AGENTS.md`（IDE 对所有 AI 会话自动加载的唯一保证入口）。
- 非目标：
  - 不改造既有 6 文档管线结构与 R10 签认体系（只补判定协议与豁免权条款）；
  - 不做变更探测机器门禁（2026-10-29 责任人裁决：太复杂难落地，豁免本质是人的判断，机器替代要么误伤要么可绕；label / PR 签字行 / 登记文件 / 规模线 / 红灯无视合并五形态全数否决，详见 design.md 备选表 B）；
  - 不做签认时间戳 / git blame 自动核验（时间戳可被 rebase/squash 重写，弱信号且误伤合法流程；`check_docs.py` 的 planned enhancement 本批不动）；
  - 不做"AI 是否输出了判定单"的运行时监控（判定单靠规范注入 + 责任人抽查 + git 授权闸二次把关）；
  - 不引入本地 pre-commit hook（不进仓库分发、`--no-verify` 可绕过、跨机一致性差）。

## 用户场景

1. **新任务开工**：AI 探查现状并呈报开工判定单（情况分析 / 建议与理由 / 路径选项全呈现 / 停等请求）→ 责任人裁决（同意 / 否决 / 修改，可推翻 AI 任一判断）→ 按裁决路径进入管线或豁免通道。
2. **越权可追责**：AI 未经判定单直接实施 → git 授权点暴露（人批准 commit 前即发现并纠正）或事后评审发现 → R10 责任制 + git 历史定位决策缺失环节，追责有据。
3. **新 AI 会话冷启动**：AGENTS.md 经 IDE 自动注入 → 任何 AI（无私有记忆）都知道开工判定单协议、豁免权归属、git 逐条授权纪律与规范入口。

## 验收标准

- [ ] `DEVELOPMENT.md` 含 AI–人协作流程条款（开工判定单必输出、停等裁决）与微改动豁免判定权条款（AI 只能提议，裁决与豁免留痕归责任人）；
- [ ] `AGENTS.md` AIxCoding 段含 AI 行为协议摘要（开工判定单 / 豁免权归人 / git 逐条授权 / 聊天认可≠实施信号）；
- [ ] git 写操作逐条授权成为 `DEVELOPMENT.md` 条文；
- [ ] 既有门禁不受影响：`check_docs.py` 全绿、CUSTOMIZATIONS.md 生成幂等（AGENTS.md 改动后重跑生成器 diff 为空或纳入提交）。
