```

合并规则（manual-version-update SKILL）：

  本轮 theirs 6 处均未改（= 0.35.1 官方文本套口径）→ 全部取 ours 官方新文本 + 套定稿口径。
```

证据确认：sessions `-` 侧 = 跨页搜索（release notes 新功能）、skills `-` 侧 = 两级子目录
（release notes 第 6 条）、getting-started `-` 侧"单行与多行引用统一为块引用"（release notes
第 2 条）——三处全部指向 `-` = 0.35.2。

### docs/ 镜像追平（责任人 2026-11-11 裁决，修订原"docs 不动"口径）

## 备选方案对比

## 对上游隐式行为的假设

1. **官方 release 不随发手册 md**：官方手册源在上游 repo `docs/{zh-Hans,en}/`，release 资产仅
   二进制/whl——手册同步以 `git fetch <upstream> tag v0.35.2` + `git show` 取文件（实测成立）。
2. **官方改动范围判定基准**：工作树 `docs/`（0.35.1 镜像）与 `v0.35.2` tag 的 diff 即官方
   手册改动全集（本轮 4 文件 12 行；`docs/index.yaml` 无变化——基线章集合不变，书签 PARTS/SUBS
   无需改）。
3. **汇编结构稳定性**：0.35 基线章体 = 对应 docs 文件全文原样嵌入（首行 h1 = 章名），章间
   `---` 分隔、章体末尾保留一个空行——章级点替换以此结构为边界假设（实测成立）。

## 风险与最坏情况

- **官方 diff 方向误判**：段落替换方向颠倒会把手册回退到旧行为描述。缓解：三重证据交叉确认
  （见上）；替换后与基线/定稿 diff 逐行核对（实际执行：官方汇编 diff 恰好等于官方改动，定稿
  diff 恰好 12+/12-）。
- **口径遗漏**：官方新文本里的品牌字面量漏改。缓解：手册自检品牌扫描 0（实际执行全绿）。
- **最坏情况回滚**：git checkout `aixcoding/manual/` 10 文件即还原；桌面产物按旧版重出即可，
  无代码纠缠。
