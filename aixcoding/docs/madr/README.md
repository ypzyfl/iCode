# madr/ —— 轻量决策记录（MADR）

> ADR 的轻量下位档。机制全貌（档位裁定、详证强约束、哨兵、审计、升格）见 `docs/standards/adr/decision-log--dual-tier-decision-records.md`；现行规范条款：`DEVELOPMENT.md` R8/§6、`DIRECTORY.md` §2。

## 什么时候在这里落条目（档位规则）

- ✅ **豁免区微改动中的小决策**（豁免三条件已含"未命中 ADR checklist"）：AI 起草条目随 PR 提交，commit 授权前呈报附全文请责任人表态"落/不落"（无表态追问不得默认）
- ✅ **纯讨论/否决决策**（R8"决定不做"，无改动载体，未命中 ADR 判定 checklist）：AI 对照 checklist 给"出 ADR / 落条目"二元建议，人裁决
- ❌ 完整管线功能内的决策——由 design.md / ADR 承载，本目录不涉足
- ❌ 命中 ADR 判定 checklist 任一（认真权衡过备选 / 撤销代价高 / 约束未来 / 依赖上游私有行为）——出 ADR；起草时发现否决项被认真权衡过 = 哨兵触发，勿落此

③ 边界示例（"约束未来工作模式"检验）——反例（落 MADR）："verify.py 输出摘要取尾部 N 行而非全量"——一次性实现选择，后来者看代码即懂，不约束后续工作；正例（出 ADR）："mock 专区维持 stdlib-only"——约束未来所有 mock 开发的工作模式，后来者会问"为什么不能用 httpx"。

## 条目命名与模板

`YYYY-MM-DD-主题.md`（一文件一决策；append-only——决策内容不回改，改决策 = 新条目；typo/失效链接等非决策性修正可原地改）：

```markdown
# <主题>

- 决定人：<拍板者，多人则首位为最终拍板>
- 背景：<为什么需要决策，1 行>
- 决定：<选了什么，1 行>
- 否决项：<为什么不 X，1 行，无则省略>
- 详证：本 PR / PR #NN / <commit> / <仓库文档路径>
```

## 字段语义

- **决定人**：归属事实记录（AI 按实际拍板事实填写，人 review 校正），非签认——条目批准链 = commit 授权前表态 → merge 事实 → peer review 核对项。**身份解析**（名字从哪来）：①有任务载体的，取其文档头部"责任人"字段（git 可查，最可靠；R10 唯一责任人制——多人讨论的最终拍板归属仍是责任人）；②纯讨论场景取对话中拍板者的表明身份；③不确定时**禁止猜测**，commit 授权前呈报中一并询问确认。**填写来源（按序）**：① 对话中责任人的明确拍板（任务指令/判定单/实施呈报/评审表态）；② AI 建议经呈报获责任人**对该决策内容**的明确认可（R10 责任人对产出负责；**普通 git 写授权不构成认可**——条目落盘仍须 commit 授权前明确表态"落/不落"，无表态不得默认）；**责任人从未表态的纯 AI 实现选择不得直接填"决定人=责任人"**——先在实施呈报中明示该选择并获认可（转化为②）方可落条目；commit 授权前呈报表态为字段准确性的最终锁定（人见字段，认可即确认、不符即纠正）；
- **详证**：强约束——决定人 + 决定内容必须被详证载体严格支撑，纯对话不构成有效详证、须先外化。**默认且合法载体 = 本 PR**：豁免区拍板现场即本 PR 的 commit 授权前呈报，决策要点写入本 PR 描述即完成外化；"本 PR"即自足——条目与 PR 同体（diff 同源），归属经 `git log --follow` / blame 可查，**无回补编号动作**。决策现场在更早处（旧 PR / commit / 批次文档）时指向之。
