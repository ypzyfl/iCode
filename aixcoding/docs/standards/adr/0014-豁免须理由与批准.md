## 背景

豁免（对既有规则/门禁/约束的个案性绕过）在本仓多种形态并存：架构豁免通道（ADR-0011 建立、ADR-0013 移除）、ruff noqa 与 per-file-ignores、测试 skip/xfail、CI 门禁跳过、约束例外。ADR-0013 裁决确认价值取向"豁免机制是升级摩擦的永久来源"，但仅覆盖架构豁免一类；其余豁免面此前零管控——lint/测试红时执行者（含 AI）可自行加豁免绕过，坏写法与坏实现借此合法化：豁免事实上是绕过设计约束的后门（有意偷懒与无意模仿存量先例两条路径）。局部实践已有先例：ruff-test-exemptions 批次（PR #71）以 design 留痕管住了单次豁免决策，但属批次自觉而非普适规则。

## 决策

新增规范 R13「豁免须理由与批准」：

1. 豁免封闭枚举四类（架构豁免通道登记 / ruff 豁免新增 / 测试豁免新增 / CI 门禁跳过），枚举外新豁免形态由责任人裁决入列；流程豁免（§4.2/§6）除外，归 ADR-0012 既有管控；
2. 默认立场：豁免是穷尽正当路径后的设计后备，不是实现选项（附判据正反例：RUF001 豁免定制测试中文断言 = 结构性冲突正当后备；未查根因即 skip 偶发红测试 = 仅因不方便，拒绝）；
3. 新增豁免须责任人批准，AI 不得自行添加；呈报三要素（形态 / 逐条理由 / 已尝试的正当路径）；
4. 留痕：就地一行注释含理由 + 批准指向（PR 编号或批次 design/ADR——git 可查授权凭据）+ PR 变更导览豁免清单（§7），评审逐条过目；
5. 档位分级复用既有链条（落上游文件的豁免叠加 R2、通道重建叠加 ADR），不新增登记形态；存量豁免不溯及。

## 理由

1. 豁免的实质是"承认某约束不适用于此个案"——这是设计判断，按 R10 逻辑归责任人，不应由执行者自行做出；AI 在约束挡路时的系统性倾向是绕过（修不过就豁免），须显式停等点拦截。
2. 审批落点取 PR 轻量裁决而非逐条独立审批或集中登记文档：豁免天然出现在 diff 与 PR 里，复用现有载体零新增机制；逐条重型停等对 noqa 级豁免不成比例；集中登记表为 ADR-0012 理由节 3 已否决的同构形态（过度设计），且与 ADR-0013 最小足迹取向冲突。
3. 批准凭据必须落 git 对象：PR body 可变、blame 不可查（ADR-0012 理由节 2），故就地注释承载"理由 + 批准指向"——注释从解释升级为授权凭据；理由注释同时堵无意路径（后来者看到"经批准的个案 + 为什么"而非裸先例，先例模仿是无声扩散主通道）。
4. 封闭枚举使判定可机械匹配（防规则自身变判断负担，对齐修订元规则）；架构豁免通道类为前瞻条款（通道不存在时永不触发，零判断成本，且是档位分级"重建叠加 ADR"的挂点）。
5. 工具化盘点列为后续增强而非前置：规则先行、机器跟进（修订元规则"宁可交给机器"方向的渐进落地），不阻塞防线建立。
