## 背景

`batches/guard-hooks` 按「等价迁入」落地的规则包是单一处置模型：表里 `confirm` 一律先按
block 落地，网络按白名单（只放回环）。现场误报把日常开发打断到无法工作——命令链接
`&&`、Shell 内建 `source`/`eval`、提问中出现注入 payload 字符串、任意非回环 IP——于是
**PR #129（`019abe38`）把两个受管 hook 出厂全停**。全停是临时态：规则包在、hook 不跑，
保护归零。误报复审（用户提供《iCode 安全护栏测试用例：confirm 分档 + 网络黑名单》及
对应改动包）给出分档结论：不是「拦得太宽」这一层的问题，而是**处置模型缺档**——
「必误报」「中高风险」「真危险」被压进同一个 block。

## 决策

护栏安全语义从「默认拦、白名单放行」调整为「**分档确认＋黑名单拦截**」，并恢复出厂开启：

1. **删除** 7 条几乎必中日常开发的规则：`IN-03`（SQL 注入 payload）、`IN-04`（XSS payload）、
   `IN-07`（同义语义簇）、`T-SHELL-03-1`（命令链接）、`T-SHELL-04`（Shell 内建）、
   `T-PY-02`（字节码自省）、`T-NET-02`（网络默认处置）；
2. **7 条中高风险规则改 confirm，出厂 `confirm_disposition: ask`**（`IN-05`/`IN-06`/`IN-08`、
   `T-SHELL-01`、`T-FS-02`/`T-FS-03`、`T-OUT-01`）：Hook 写 `action: ask`，引擎弹确认框
   ——继续放行、拒绝拦截；客户端无法询问（headless）或用户拒绝时按 block 兜底
   （fail-closed，依赖引擎既有 `GATED_EVENTS`/`_confirm` 语义，零上游改动）；
3. **网络白名单翻转为黑名单**：出厂含禁止攻击目标 `*.bocsys.cn` 与 `22.122.49.168/32`；
   求值顺序＝**回环最先完全豁免**（`127.0.0.0/8`、`::1`、`localhost`、`*.localhost`——
   危险端口也不例外；2026-11-26 责任人 F2 裁决，适配改动包 (4)）→ 危险端口
   （22/445/3389/3306…）对非回环目标恒拦 → 黑名单主机/网段；其余地址放行；
4. **两个受管 hook 出厂重新开启**（`hooks.yaml` `enabled: true`；`T-OUT-02` 出厂仍关）。

## 理由

- **全停不可持续**：保护归零与「有护栏」的产品定位矛盾；PR #129 的停用注释自述为
  temporary shutdown。
- **逐条现场 disable 治标**（否决 A）：误报规则人人必中，逐机手工关闭口径漂移，且
  `disable` 表达不了「确认」这一档。
- **只删规则不引入 ask 减半不除根**（否决 C）：`rm -rf /tmp/xx` 清理临时目录、读
  `.ssh` 排查部署问题这类操作仍会被 block 打断；ask 档让用户裁决，护栏退到「提示」
  而不是「替用户决定」。
- **网络黑名单的理由**：白名单语义＝「拦一切非回环」，正是误报重灾区；黑名单＝只拦
  明确禁止攻击的目标，未列入一律放行——与「护栏拦攻击、不拦日常」的定位一致；
  `*.domain` 后缀锚定防 `notbocsys.cn` 子串误伤。
- **回环最先完全豁免（F2 裁决）的理由**：「危险端口恒拦」与「回环恒豁免」在
  `127.0.0.1:6379` 这类交集上原是两条绝对化承诺的隐性冲突（测试用例 D3/D4 各测一面、
  未覆盖交集，实现静默选择了前者）；本地服务排查（DB 端口 3306/5432/6379/9200/27017）
  是高频开发场景且本机回环不构成对他人资产的攻击面——豁免优先级显式定为回环最高，
  并把豁免范围从回环 IP 扩展到 `localhost` / `*.localhost` 主机名（RFC 6761 伪 TLD），
  消除「名字与 IP 待遇不一」的新误报源。
- **ask 零成本**：引擎已支持 `action: ask`（门控事件确认卡、不可询问 fail-closed），
  本决策只消费该契约，不改上游一行。

## 后果

- 出厂黑名单成为**禁止攻击目标清单**：新增攻击目标须改 `pack/rules.json` 并发版
  （现场改已安装副本会被下次启动覆盖）。
- 已删 7 条规则加回前必须过误报评估，并同步自检「保持删除」回归用例。
- confirm 分档依赖引擎 ask 契约：上游升级时核对 hooks spec（`GATED_EVENTS`、`_confirm`
  兜底语义——declined/timed_out/unavailable → blocked）。
- 白名单时代「内网一律拦」的保护不复存在：内网访问治理移交黑名单条目与客户环境管控
  （质量属性裁决序中安全为硬约束的边界＝威胁模型：护栏拦「攻击目标」而非「一切内网」）。
- 已部署机器升级重启后从「全停」变为「分档开启」，中高风险操作开始弹确认框——属目标
  行为，发布说明需显著标注。
