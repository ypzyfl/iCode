> 本文为决策时点快照；现行规则以 `DEVELOPMENT.md` §4（AI–人协作流程 / git 写操作纪律）、§6（微改动豁免判定权）为准。

## 背景

2026-10 连续发生 AI 越权事件（PR #67 扫描器行为变更越权、auth-logging 批次跳过文档管线直接准备实施、git"逐条执行"承诺未兑现即连贯执行）。复盘确认规范本身完备（§4 铁律、§6 管线、R10 签认均已存在），缺口在执行结构：规范是"知识"不在 AI 决策现场（按需读取，任务中段上下文里只剩"用户最新一句话"）；开工流程判定无协议（§6 豁免三条件未写判定权归属，AI 可自判自执）；git 写操作授权纪律只存在于 AI 私有记忆（换一个无此记忆的 AI 即失效）。完整分析见 `aixcoding/docs/ai-gates/design.md`（签认 2026-10-29）。

## 决策

采用**两层防线**治理 AI 流程违规，并否决机器变更探测层：

1. **第一层（软约束进决策现场）——开工判定单协议**：任何免判定清单外任务，AI 第一步呈报"情况（分析结果）+ 建议（附理由）+ 选项（路径全呈现）+ 停等"开工判定单，责任人裁决（可推翻 AI 任一判断，含"条件不满足"结论本身）。豁免判定权归责任人：AI 只能提议、不得自批豁免、不得现场判断任务归入免判定清单（清单由规范预定义，AI 只做机械匹配，拿不准即停等）。协议条文落 `DEVELOPMENT.md` §4.2，摘要经 `AGENTS.md` 注入所有 AI 会话（IDE 自动加载的唯一保证入口）。
2. **第二层（物理闸门 + 追责锚）——git 写操作逐条授权条文化**：每条执行后停下汇报、等下一条明确指令再继续；任何越权产物要进仓库必经人批准 commit/push，批准即审查时机；开工裁决 + git 授权批准 + R10 签认 + git 历史构成完整可追责链。

## 理由

- **豁免权归人**：两次越权的共同形态是"自判自执"——判断者与执行者同体，无制衡。判定单把判断权交还规范（预定义清单）与人（现场裁决），AI 只剩机械匹配与提议职能；人的裁决成本≈看一张表回一句（审而非想）。
- **否决变更探测（check_change_set.py）**：机器不做"新特性/轻微改动"语义判断，豁免本质是人的判断，机器替代要么误伤要么可绕。其豁免通道五形态全数难落地（R8 否决留档）：
  1. PR label——无权限控制、无签字语义；
  2. PR 描述签字行——body 是可变的平台侧对象，非 git 对象，blame 不可查；
  3. exemptions/ 登记文件——过度设计：防的风险（豁免未经人决策）已被判定单在源头覆盖；签认重量应与变更重量成比例，百行级微变更不值得签字文书；
  4. 规模放行线（≤100 行）——机器判"轻微"与"豁免权归人"自相矛盾；边界争议（99/101 行无语义差异却红绿不同）与拆 PR 绕线使其难落地；
  5. 红灯由人无视合并——太复杂；豁免频繁时"见红就合"的红灯疲劳会钝化信号。
- **追责优先于机器门禁**（责任人 2026-10-29 裁决）：只要第一步人做决策，决策即可追责（开工裁决 + git 授权批准 + R10 + git 历史四级留痕），参与者会在可追责下自觉遵守——这是制度基础；机器门禁的复杂度与维护成本超过其拦截价值。
- 同族否决：本地 pre-commit hook（不随仓库分发、`--no-verify` 绕过、跨机不一致）；签认时间戳与提交先后核对（时间戳可被 rebase/squash 重写，弱信号且误伤合法流程）。

## 后果

- 所有 AI 会话（含无私有记忆的新会话）开工必遇判定单协议（AGENTS.md 自动注入覆盖）；责任人每任务新增一次开工裁决交互；免判定清单内任务（活文档追加/只读/已签方案内实施）AI 一行报备后直接执行，不增负担。
- git 写操作逐条停等从 AI 私有记忆约定升格为规范条文，对一切 AI 生效。
- 残余风险明示接受：AI 不经判定单直接干活时无机器兜底——依赖 AGENTS 注入覆盖、责任人抽查（"无判定单即违规"为抽查信号）、git 授权闸二次把关与事后追责。
- 任何人将来重提"变更探测 / 机器豁免通道"时，本文理由节即答案；实践若证明两层防线不足（如判定单被系统性无视），出新 ADR 取代本文。
