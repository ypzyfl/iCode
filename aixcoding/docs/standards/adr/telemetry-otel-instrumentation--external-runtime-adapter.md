## 背景

责任人要求从官方源码分析零源码修改的埋点路径，后续明确不限制于0.35.2，以0.36.0进行首轮模拟，并适配未来官方版本。首轮官方提交为 `78802f87d07f053fe560d680e4696c2bf322e2c2`，0.35.2 `2fd777f626649d53d7ccd701e26a1a7ada569ce8` 用作兼容回归。已交付fork仅提供业务契约。两版已有OTel和运行时快照，但公开extension不暴露全部企业事实；session重建承担额外保存/压缩/一致性复杂度。

## 提议决策

采用独立伴随 instrumentation 包，公开接口优先；必要的运行时包装显式安装、版本限定、清单登记、可诊断和可卸载。所有企业事实、关联、编码和发送留在包内，官方文件保持字节不变。官方管理 OTel provider；OpenLLMetry 仅按缺口选用 instrumentation，不默认启用全量 SDK。

稳定业务核心只依赖能力契约，宿主路径和阶段语义由适配家族/绑定配置提供；注册表区分source-reviewed、runtime-verified、qualified与unsupported。同一家族可覆盖多个已验证版本，不按版本复制业务实现。0.36.0首轮、0.35.2回归分别运行真实门禁后才晋级，未知版本不默认生产启用。未来变更只允许发生在外置包，不改官方源码，不用宽版本范围或相同签名替代语义证据。

首版企业业务事件直接兼容现有 HTTP，不依赖采样 spans 生成业务记录。业务 ID 保持独立，不直接替换成 trace_id/span_id。ACP 最终身份和快照来源必须真实同次执行，不能依赖 session-latest 或磁盘重读猜测。

独立包优先另仓分发，不在本仓根 aixcoding 偷放产品代码。当前仓若要建立独立包落点、扩展构建或运行时接触登记机制，须先按既有规范另行批准；本 ADR 草案没有修改任何规则。

## 备选与理由

- 保持现有源码接线：作为生产回退，不能满足新目标的官方源文件零改动。
- session 主链：不推荐继续作为目标，因为通用事实已在运行时，重建增加间接耦合；正式替代旧决策需责任人签认，不擅改历史 ADR。
- 仅公开 OTel/extension：最先复用，但不足以保证快照/关联/ACP 完整业务。
- 全量 OpenLLMetry SDK：可能重复采集和争用 provider，先按需评估单项。
- 静默全局 monkey patch：不采用；接触面必须显式、版本验证并纳入运行诊断，不以零 diff 掩盖风险。

## 后果与门禁

官方源码哈希不变不等于升级零成本，私有方法仍有语义耦合。每个目标版本必须通过原版G1–G4、T1–T16及业务/发行组合验收后才能获生产资格；main固定SHA只作预警。关键事实无法取得或流式行为无法保持时标unsupported，宿主继续，不自行补官方源码。0.36.0工具结果hook等实际差异须归一，不能把两版同签名写成已经运行兼容。

依赖引入、独立包仓库、发行形态和包装登记策略仍待裁决。本文不授权生产编码或第三方安装，未改变已签 design 的范围。后续重大机制变更遵守决策更新流程。
