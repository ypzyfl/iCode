## 背景

治理三层（ADR / 六文档管线 / 微改动豁免）存在决策落点断层：①"够不上 ADR checklist 但有决策含量"的中间地带决策沉没在 PR 描述（GitHub 资产）或人脑；② R8"决定不做的事必须记录"有义务无统一落点；③ ADR 判定③门槛宽（"后来者会问为什么"几乎即中间地带定义），严格执行则 ADR 泛滥、软性收窄则③形同虚设，灰色地带无合法留痕出口。方案经三轮外部评审 + 责任人五次修正 + 复审收敛（全过程见 `batches/decision-log/design.md` 评审记录节）。

## 决策

**决策记录双档制**：正式 ADR 档（`standards/adr/` 全局池，语义 ID，既有不动）+ `aixcoding/docs/madr/`（轻量下位档，本决策新增）。

**载体形态**：目录 `aixcoding/docs/madr/`（与 `standards/` 平级，工程记录不入规范目录；目录级 `README.md` 为使用说明，非条目）；文件命名 `YYYY-MM-DD-主题.md`（零分配协调、零抢号冲突、文件名字典序即时间序；**落点目录与命名形态即档位信号**：`adr/` 语义 ID = 正式档，`madr/` 日期 = MADR）；append-only（决策内容不回改，改决策=新条目；typo/失效链接等非决策性修正可原地改）。模板（4–5 行）：

```markdown
# <主题>

- 决定人：<拍板者，多人则首位为最终拍板>
- 背景：<为什么需要决策，1 行>
- 决定：<选了什么，1 行>
- 否决项：<为什么不 X，1 行，无则省略>
- 详证：本 PR / PR #NN / <commit> / <仓库文档路径>
```

**机制**：

1. 防腐烂对称：漏登=仅缺失（回 PR 承载现状，永不误导）；滥登=记录不存在的决策（与 INDEX.md 失真同构，血亏）——由机制 2/3/4 封堵，不得以"写了就赚"单方向辩护。
2. 详证强约束（否决性条件）：详证必须指向 **git 可查对象**（PR 描述/commit/仓库文档），纯对话拍板不构成有效详证、须先外化；决定人 + 决定内容必须被详证严格支撑；peer review 固定核对项一条（档位恰当 + 详证支撑）。
3. 档位裁定（AI 建议人裁决，分场景二元）：**豁免路径微改动**——豁免资格已含"未命中 ADR checklist"（三条件②），档位只剩**落条目/不落**；AI 起草条目随 PR 提交（起草=建议实体化，非决定），**commit 授权前呈报附条目全文请责任人明确表态"落/不落"，无表态追问、不得默认**（三层过滤——豁免区少数/"值得留痕"再滤/重要否决走 ADR——下预期低频，月均个位数，逐条表态负担可控；表态与 git 写授权同回合，零新增停等点）。**纯讨论/否决决策**（R8 场景，无改动载体）——档位二选一**出 ADR / 落条目**，对照 checklist。**完整管线内决策由 design.md/ADR 承载，madr/ 不涉足**。免判定清单不扩 madr/：条目落盘必经人。
4. 写时哨兵：起草条目时发现否决项被**认真权衡过** = 命中 ADR 判定① = 豁免三条件②不成立——非档位选择，是**豁免资格失效信号**：停等呈报、退出豁免走完整管线；决定涉及上游接触面同理（条件①失效）。
5. 事后低频审计：AI 于既有节律点（升级批次启动时）扫描 madr/，呈报一行结论（该升格滞留/同主题堆积/可疑档位 + 条目频率观测——持续月均 >5 条时建议重估裁决形态，备选含批量集中裁决），人裁决处置。
6. 升格通道：条目事后证明撤销代价高/约束未来 → 出正式 ADR 引用之（按文件名）；条目本体不回改，升格信号由 ADR 侧单边引用承载。
7. R8 落点（场景分流）："决定不做"按场景分流——完整管线内由 design.md 备选对比承载；微改动豁免区可选落 madr/；纯讨论（无改动载体）是 madr/ 最典型场景，重要否决（认真权衡过备选）仍命中 ADR 判定①，走 ADR。
8. 必要性定位：防 ADR ③稀释（双向：泛滥与软忽略）+ R8 落点补齐；不以"中间地带决策"为主论据（③字面已覆盖大部分中间地带，madr/ 是③松紧执行的灰色出口而非③之外领地）。
9. 负担红线：无新增独立停等点、无新增走 R10 签认机制的文档（**决定人字段是归属事实记录而非签认动作**——AI 按实际拍板事实填写、人 review 校正；条目批准链三层：commit 授权前表态 → merge 事实[同 R13"批准指向 PR"凭据模式] → peer review 核对；加签认字段组即成小 ADR，非轻量档形态）、无新增 CI 门禁、无新增工具校验（check_docs 零适配；格式校验只防漏填不防伪造，留作后续增强）。
10. rule of three：同类微改动累积（约第三次，含重访前次结果）→ 演进脉络固化进对应主题既有文档（批次活文档/规范条目，免判定清单①活文档追加）；无对应文档且值得独立追溯 = 命中 §6 既有退出条件走完整管线。madr/（决策点时间线/临时态）与活文档（主题稳态聚合）构成同一条信息生命周期的两段。

**与标准 MADR（adr.github.io）的差异**：三删（Status 状态机——append-only 无状态；Considered Options/Pros-Cons 展开压缩为"否决项"1 行——展开即命中 ADR 判定①，是档位边界执行机制；Decision Drivers/Consequences——并入背景 1 行）+ 两增（决定人——人机协作下 blame 不可信；详证强约束——封堵 AI 伪决策留痕）+ 一改（编号→日期命名——抢号冲突点 + 档位信号）+ 流程包裹（AI 起草 + 人表态 + 哨兵 + 审计；标准 MADR 无落盘流程约定）。设计取向：把 MADR 从"轻量但自足的记录格式"改造为**档位受控的 ADR 下位档**——删减降低其替代 ADR 的能力（防弱化漂移），增加封堵伪造风险（防滥登）。

## 理由

被否决备选及死因（详见 `batches/decision-log/design.md` 备选对比）：**单文件 decision-log.md**——并行 PR 冲突集中点（责任人裁定）；**编号目录 NNNN-主题**——抢号 = ADR 目录已付学费的冲突点（责任人裁定）；**不引入维持现状**——R8 无载体 + ③无泄压阀缺口保留（三轮评审收敛否决）；**并入 ADR 降格式**——稀释 ADR 严肃性与签认体系；**工具化门禁**——只防漏填不防伪造，违负担红线。目录名 `madr` 而非 `decisions`：与 `adr/` 术语对称、MADR 业界共识指向、独特检索 token（责任人裁定）。

## 后果

- 新增 `aixcoding/docs/madr/` 目录与双档判定义务：AI 接任务遇决策落点须按机制 3 分场景给二元建议、人裁决；微改动豁免 PR 含决策要点时须走"起草→呈报表态→入库"流程。
- R8"决定不做"有了统一落点；ADR ③获得泄压阀（档位裁定三层机制防双向漂移：事前建议/写时哨兵/事后审计）。
- 规范联动已落地：DEVELOPMENT.md（R8 落点/§6 两句/平铺枚举）、DIRECTORY.md（判定树/总蓝图）、README（结构图/速查表）、两 HOWTO（R8 摘要/评审核对项）。
- 回滚：删 madr/ 目录 + 本 ADR 标"被取代" + 撤联动，零代码影响。
