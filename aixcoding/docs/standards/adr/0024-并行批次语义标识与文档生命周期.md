## 背景

并行批次合并时，定制点 `C###` 的全局高水位和连续孪生区间、ADR `NNNN` 的目录最大号加一，均使编号分配成为跨分支协调点；INDEX 的逐批追加和 ROADMAP 的多类事实汇总又形成共享文档写热点。冲突解决还伴随测试名、design 登记、ADR 文件与引用、路线记录和升级事实的关联修改。总目标不是消灭一切文本冲突，而是让常规冲突无需人工选号或方案裁决，能由 AI 在明确边界内机械修复并用门禁验证。

ADR-0015 已确立 `(落点, marker 锚)` 是对账主键、ID 只是沟通标识，因此可以改变 ID 分配方式而不改变 marker 对账模型。ADR-0016 确立的 batches 单层平铺仍满足目录稳定性，但其 INDEX 全量人工表已成为并行写入点。责任人进一步明确：INDEX 与 ROADMAP 均随本批物理删除，ROADMAP 不等完整迁移或验收；迁移项由责任人自行跟踪，历史内容从 Git 获取。

## 决策

1. **定制点采用批次命名空间语义 ID**。新 ID 为 `<batch-slug>:<point-slug>`，前缀须与所属批次目录一致；完整 ID 在 active + retired 范围全局唯一且永不复用。新孪生组使用一个组 ID + 预期计数，不再分配连续区间。旧 `C###`、旧区间和 tombstone 永久兼容，不做全库重编号；对账主键不变。新测试以行为命名，不嵌入登记 ID。
2. **集中导航改为按需只读视图，INDEX 随本决策物理删除**。`docs_report.py` 自动扫描 batches 一级目录并复用现有 requirements/design/plan 的 H1，零写入、无生成物、无 freshness 门禁；`aixcoding/README.md` 速查表以相邻入口承载批次目录全景（`docs_report.py`）与定制点全景（`gen_customizations.py --report`），其余少量固定入口同样由 README 承载。凡有批次目录的微改动均纳入；只在 PR 描述留痕的无目录微改动不在展示或统计范围，通过 GitHub merged PR 视图按描述人工识别，不要求补 `micro/` 或精简批次目录，工具不联网、不调用 GitHub API、不猜测分类或计数。历史批次无需补导航元数据，历史记录中的 INDEX 叙述不回改，普通功能 PR 不设 INDEX 缺行门禁。
3. **ROADMAP 随本决策直接物理删除**。不等待 telemetry 数据管道对拍、完整验收或旧分支归档，不设置最终迁移/收尾批次前置；迁移项由责任人自行跟踪，不在仓库另建替代台账。文件删除后不保留退役标记、冻结档案、重定向或占位文件，历史内容从 Git 获取；删除不代表迁移完成或验收通过。README、UPGRADE-RUNBOOK 及其他现行引用同步移除，gen_customizations 的 docstring 与报告标题去除“ROADMAP §4 输入”耦合；历史叙述不批量改写。
4. **ROADMAP 删除不扩散到批次授权资产**。各批次 design 的 R2 审批、现役定制点登记和 tombstone 继续保持扫描和现行效力，不随路线文档删除、归档或移动。
5. **ADR 全部进入全局池；此后新 ADR 采用批次命名空间语义 ID**。新 ID 为 `ADR-<batch-slug>--<decision-slug>`，文件名为 `standards/adr/<batch-slug>--<decision-slug>.md`，不使用 Windows 文件名禁用的冒号；不区分全局/功能决策，不新建或保留功能池，来源批次由 ID 表达。存量 `batches/guard-switches/adr/0001-guard-write-scope-factory-default.md` 随本决策迁为 `standards/adr/0023-guard-write-scope-factory-default.md`（标题 `ADR-0023`）：该决策发生于 2026-11-05、早于本文，按事实顺序占用 0023；本文为 2026-11-10 的后续治理决策，占用 0024。二者是语义 ID 规则生效前的最后两个旧数字 ADR；此后新 ADR 不再分配数字编号。0023/0024 已由本批预留，实施窗口内并行批次不得占用；0023 文件虽在实施时才迁移，预留自本决策草案核查时生效，发现占用即停等协调。guard-switches 的 requirements/design/plan 三个文件内全部旧引用（当前共 6 处）及 ADR 自身 H1 随迁移更新。新语义 ADR 的完整 ID 全局唯一；check_docs 同时支持旧数字后继与新语义后继，并校验 ADR 全局池位置、批次归属、唯一性与文件存在性。
6. **机械改号获得窄口径预授权，算法与证明均确定**。已合并侧不改；仅允许处理未合并批次已签 design 变更清单内文件。单个旧 `Cnnn` 的首选 point-slug 固定为 `legacy-cnnn`，旧数字 ADR 固定为 `legacy-adr-nnnn`；`legacy-` 为机械修复保留前缀，旧区间/孪生组不自动转换。重复条目分别按 design 物理位置或 ADR 旧路径排序，首选 slug 冲突时按 occurrence index 起递增分配 `-m1-<n>` 首个空闲后缀；同一输入只能得到同一结果。引用归属有歧义即停等。只读 `check_id_only.py` 必须重算映射并证明登记字段、R2 表、ADR 决策节及全部其他内容除声明的 ID/路径外零变化，失败即关闭预授权；满足 ID-only 和门禁通过时才不重复签认。
7. **主干增加边界明确的文档闭环门禁**。`check_docs.py --closure` 在 `pull_request`（含特性分支发起的 PR）及 `push` 到 `main_aixcoding_cli` 时执行，本地手动默认模式仍允许草案：决策档不得为草案、批次必备六件不得缺失、精确 ADR 引用必须解析到已确认/被取代文档；对 plan 仅识别含“任务/状态”列的 Markdown 表格中、状态完整匹配“完成”或“完成（...）”且任务或状态单元格含独立 self-review/verification token 的结构化记录，要求对应文件存在、含 H1 与非空白正文，self-review 另过既有签认校验，不承诺识别自由文本中的所有虚假陈述或证明实际执行真实性。规则生效后，§6 豁免微改动不新建 batches 目录，需要目录导航或独立追溯即放弃文档管线豁免并满足六件；任何新增 batches 一级目录均无微改动缺件例外，docs_report 所纳入的缺件微改动目录仅限封闭清单中的存量形态。既有缺口以 `origin/main_aixcoding_cli@95e23add` 盘点，初始清单由本 ADR 签认批准并存入机器可读 `closure-exemptions.toml`；常态只减不增，文件补齐时在同 PR 删除精确豁免，任何新增或扩大须另出 ADR 并由责任人签认。R13 封闭枚举新增“文档闭环存量豁免的新增/扩大”类别，两份评审模板同步。`guard-switches` 的未签 ADR 与缺失 self-review/verification 随本决策先行修复，最终 closure 验证置于修复之后，不倒填历史。

## 理由

- 批次目录本来就是稳定且唯一的所有权边界，以其作为 ID 命名空间可让并行分支无需协调；保留完整 ID 全局唯一和 tombstone，可同时防止复制错误与历史引用复用。
- ADR 统一全局池可取消“全局/功能”的分类判断和后续移池成本；批次来源已由 ID 保留，存储位置无需重复表达。guard-switches 决策先于本文发生，迁入全局池时按时间线占用 0023、本文顺延 0024，保留决策顺序的可读性；两者均属规则生效前遗留，因此不破坏“此后新 ADR 语义命名”的目标态。
- 集中导航的价值是“能查看全部有目录批次”，不是“所有 PR 共同编辑一个文件”，也不要求无目录微改动为了统计补文档。`llm-keyless-sdk-auth` 六件完整且已合并却从未登记 INDEX，证明人工登记在无 freshness 门禁时会持续欠账。现有 H1 已足以提供基本导航，自动目录发现比强制补三列元数据更符合最小变更；无目录微改动由 GitHub merged PR 视图承接，避免把可修改的 PR 描述或网络 API 变成离线工具真值。
- ADR-0015 退役 CUSTOMIZATIONS.md 的教训继续适用：派生视图按需输出，不把生成物重新纳入 Git 和 freshness 门禁。
- 迁移项已由责任人自行跟踪，继续维护 ROADMAP 会形成第二套事实来源；直接删除比冻结普通流水或建设替代聚合系统更简单，也不会把未完成迁移误记为完成。
- Git 已完整保存 INDEX 与 ROADMAP 的历史内容，无需为考古保留冻结文件或重定向；只清理现行入口，历史批次中的当时叙述和失效路径不批量返工。
- `guard-switches` 实证表明“CI 绿”被误当作“文档闭环”：格式校验合法接受草案，也不检查必备文件与引用。闭门模式把合并语义从字段格式升级为闭环事实；只有本地手动开发保留宽模式，特性分支发起的 pull_request 同样执行 closure。

被否决备选：

- **人工 INDEX 集成人单写**：能降低冲突频率，但保留集中文件、欠账窗口和清账成本，不作为永久目标态。
- **薄 INDEX 保留静态入口**：链接看似稳定，但批次与定制点全景已有命令真值后仍保留双入口，继续要求规范解释其分工。
- **全量分布元数据迁移**：能保留类型/简介，却要求历史批次补字段并产生长期维护义务；在 H1 足够导航时不值得。
- **ROADMAP 原路径冻结或保留重定向**：仍会维持一个已退出现行体系的文档入口和额外分工解释；Git 已能满足历史追溯，责任人又自行跟踪迁移项，无需保留文件。
- **编号预约/预留块/merge queue**：只改变协调或合并顺序，不消除编号和关联修改。
- **union/ours 自动盲合**：可能把语义冲突静默合成错误文档。
- **保留数字 ADR + 全库 renumber**：撞号后仍要修改多处引用并解释签认漂移，不能直接满足低代价机械解决目标；仅允许按本决策的批次边界算法处理旧撞号，不作为永久机制。
- **把 ADR 命名治理后置**：会保留本批明确要消除的管理改动，与总目标冲突。
- **通用自动合并机器人**：无法可靠判断业务语义，且实现和误改成本高于分布命名与窄口径规则；本决策只自动处理可证明的机械场景。

## 后果

- 冲突分为 M0（独立新增，Git/门禁直接闭环）、M1（ID-only 机械修复）、M2（行为/决策/R2 语义分歧）；只有 M1 获得窄口径免重复签认，M2 必须停等责任人。
- 本决策修订 ADR-0015 决策 2 的 ID 分配规则；其余点级登记、匹配主键、产物退役、check/report 机制继续有效。
- 本决策修订 ADR-0016 的 INDEX 全量人工表、创建时登记义务及根文件预留中的 INDEX/ROADMAP 形态；batches 单层平铺、路径稳定、design 扫描面继续有效。旧 ADR 正文不改写，现行规范指向本决策。
- 新批次只写自身目录即可获得导航；§6 豁免微改动不新建 batches 目录，需要目录即走完整管线六件，新增缺件微改动目录由 closure 拒绝，无目录豁免继续只留 PR 描述；迁移项由责任人自行跟踪，批内 plan/verification 承载各自待办和执行事实，不恢复 ROADMAP 共享记录。
- 本批直接物理删除 INDEX 与 ROADMAP，同步更新 README、UPGRADE-RUNBOOK、DEVELOPMENT、DIRECTORY 和 gen_customizations 的考古输出表述；不等最终迁移/收尾批次，历史叙述不批量改写，旧内容从 Git 获取。
- `gen_customizations.py` 支持旧数字定制点 ID 与新语义 ID；`check_docs.py` 支持旧数字 ADR 与新语义 ADR 的文件及后继校验；`docs_report.py` 提供零写入批次目录导航，含封闭清单覆盖的存量缺件微改动目录，不含无目录微改动；`check_id_only.py` 提供只读、fail-closed 的机械改号差异证明。
- M0 并行分支场景和 M1 改号演练必须证明合并不产生管理文件冲突、修复不越出未合并批次且语义字段不变；同批重复、后缀占用、歧义引用和额外内容差异均有确定性测试；CI 不因 INDEX 缺行阻塞普通功能 PR。
- `guard-switches` 的 `ADR-0023` 须由批次责任人本人按实际日期补签；self-review/verification 补做文档必须如实记录 PR #98 的历史缺口，不得伪造历史结论。存量缺口清单常态只减不增，减少豁免随补齐证据执行，新增或扩大须另出 ADR 并签认；最终完整 closure 在 guard 修复后运行。
- 若未来证明 H1 导航不足，可另行评估可选元数据；不得未经新决策恢复逐批共享写入、全库 renumber、生成式 INDEX 或 ROADMAP 替代台账。
