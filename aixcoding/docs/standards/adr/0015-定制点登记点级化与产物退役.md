## 背景

定制点登记机制原为三层：代码 marker（事实）→ design「定制点登记预告」表（语义，批次/落点级）→
`gen_customizations.py` 聚合生成的 `CUSTOMIZATIONS.md`（集中产物，git 受控 + freshness 铁律）。
2026-10-31 诊断出三个结构性问题均出在产物层：①登记源多源聚合混淆（C021/C022 双源拼接带删除线
残留）；②C 编号零持久化（扫描序号随增删整体漂移，runbook 引用曾静默失效）；③产物结构性膨胀
（登记批次级 1 行摊 22 marker，anchor/risk 全文复制 ≈15KB）。freshness 铁律另有两翻车实证
（PR #65/#67）。三轮外部 AI 评审 + 责任人终裁收敛为 C+ 方案（批次 aixcoding/docs/customization-registry/）。

## 决策

1. **登记表点级化**：一行=一个定制点（孪生组——同文件同文本 marker——合并一行：区间 id +
   预期计数校验，不依赖行序契约；组内成员不可单独寻址为显式契约边界，成员需分化时拆组+改锚走 R2）。
   匹配键=(落点, marker 锚) 前缀 + 同文件最长锚优先；登记行改动属 R10 重签范围。
2. **id 降级保留**：`C###` 为登记行沟通标识（非主键，主键=文件+符号）；分配=含退役号的历史
   最大号+1，永不复用；tombstone（退役记录小节）保高水位。尽力而为软标识——冻结前已漂移的
   历史引用不因此修复。
3. **`CUSTOMIZATIONS.md` 产物退役**：衍生物不再 git 受控，freshness 铁律整个取消；
   `gen_customizations.py` 改造为对账命令（check 默认零写入 / `--strict` CI 姿态孤儿登记升级
   error / `--report` stdout 全景视图）；升级时点证据=report 输出附该批 verification.md
   （不可变快照，无 freshness 义务）。
4. **豁免单一来源**：marker 豁免清单（4 项生成产物）从 gen 硬编码经产物中转被 R3 读回的间接环，
   改为 `_common.py::MARKER_EXEMPTIONS` 双工具直读。
5. **removal_condition 双轨**：判据类别语义（8 类）静态化于 `UPGRADE-RUNBOOK.md §5` 附录；
   逐组取值落登记表（随点演进、受签认绑定）。

## 理由

对账能力在产物机制下即已存在（生成器内双向校验 + CI 实际在跑）——本决策不是新建信任根，
是剥离落盘让既有校验直接充当门禁（校验语义更强：直接校登记↔代码一致，而非校一份衍生快照的
同步性；错误注入测试 + 零写入断言补足旧门禁从未有的自检）。多 AI 频繁换会话的团队形态下，
实时命令真值优于可能 stale 的 git 快照（stale 快照对盲目信任它的 AI 协作者是危险信号）。
被否备选的死因（评审三轮收敛）：

- **B 点级+ID 冻结+产物瘦身保留**：freshness 摩擦（机制性，两翻车实证）原样保留，且产物仍与
  登记表双载体；
- **砍 id（AI-2）**：26 文档存量引用与升级交付物惯用的紧凑表达失去现役口径；tombstone 后
  纪律成本已压低——责任人终裁留+降级；
- **E 集中台账**：脱离 R10 design 签认体系（或重发明一套近似机制），批次上下文与登记分离，
  1 责任人形态下无多人协调收益；
- **marker 内写 id**：最稳物理身份，但违 R3 单行注释口径且 R2 面扩 29 处——列为未来 marker
  规范演进候选，不捆绑本轮。

## 后果

- 定制点全景入口 = `gen_customizations.py --report`（AGENTS.md AIxCoding 段有指引）；
  新会话 AI/新人不再"打开一个文件"而是"跑一条命令"；
- marker 增删/措辞改写/文件移动 → check error 暴露 → 跟改登记行（R10 重签），id 不随跟改漂移；
  升级基线信息（上游版本/日期）迁 `UPGRADE-RUNBOOK.md` 头部「当前基线」节；
- `CUSTOMIZATIONS.md` 的全部现行引用改命令口径；历史记录档（verification/self-review/已完结
  design 等）按不改写原则留档，冻结前 stale 编号引用随引用面核查逐处勘误（首例：
  upstream-merge-v0.32.2/design.md 存活核对矩阵 C002/C007 勘误注）；
- ROADMAP 补做义务①（登记源单一化）销项；auth-stamp 待办核销（孤儿登记清零）；
- 对账命令成为新单点：盲区与旧幂等门禁相同（扫描 bug 双盲），以 9 类错误注入测试 + 零写入
  断言 + 表头损坏/代码围栏 fail-closed 补偿（围栏感知为本次实施实战修复：design 契约示例
  曾整表混入对账）。
