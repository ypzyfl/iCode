# 自审怎么做（SELF-REVIEW HOWTO）

> **给谁用**：功能作者。代码与验证完成后、提 PR 前打开本文照做。
> **一句话**：换一个与主力开发不同的 AI 评审 → 你逐条拍板修/不修 → AI 修复 → AI 复审 → 主要问题清零即收敛 → 报告你签字。
> **不吹毛求疵**：AI 评审永远能查出问题，修复所有问题的代价太高——blocker（主要问题）清零即通过，次要问题可不修。
> 规则出处：DEVELOPMENT.md §4/§5/§9。

## 一、流程（五步）

```
① 换 AI 评审：选一个与主力开发不同的 AI（不同工具或不同模型），复制 §二 模板给它，得到 findings 清单
② 你拍板：逐条看 findings，决定"修 / 不修"——你的判断是裁决，不需要说服 AI
③ AI 修复：按你的拍板修复；修复引入的新 diff 让同一评审 AI 复审（只复审增量，不重跑全量）
④ 收敛：所有 blocker 修复且复审通过即收敛——不要求零 finding，次要问题不修也通过
⑤ 报告签字：AI 生成 self-review.md（§三），你签认，随 PR 提交
```

## 二、评审 AI 指令模板（复制即用）

```
你是独立评审 AI（本次不做开发，只做评审）。请对当前工作区变更执行评审。

评审背景（规范摘要，已内嵌无需另读文件；全文见 aixcoding/docs/standards/DEVELOPMENT.md）：
- R1 非侵入优先，必改上游时少而集中（升级冲突面最小化）
- R2 上游文件的任何改动必须先获批（对照下方 R2 比对）；R3 获批的上游改动必须带 AIxCoding 单行标记注释
- R4 新增文件只允许落 aixcoding 目录（产品代码仅 src/chrys/aixcoding/）
- R5 只改任务必需内容，禁止顺手重构/升级依赖；R6 发现他人未提交改动时停止询问
- R7 "测试通过"必须附真实命令与输出；R8 文档与定制清单须同步更新
- R9 定制代码默认只依赖 chrys.foundation / chrys.kernel
- R10 签认必须责任人本人；R11 新增第三方依赖默认拒绝、须审批
- §9 降级可查：异常吞噬必须有日志/注释/计数痕迹，宁缺毋错

1. 读取 git diff（相对 <base>）与 aixcoding/docs/<feature>/design.md、test-plan.md
2. 逐项执行以下检查，输出：检查项 | 结论（过/finding）| 证据（文件:行号）
   - R2 比对：diff 中上游文件与 design.md R2 清单逐文件对名，不允许"整体一致"式结论
   - R11 比对：diff 中 pyproject.toml / uv.lock / 新 import 的第三方变化与 design.md 依赖申请节
     逐项对名；清单外引入 = blocker
   - 幻觉 API：对 diff 中每个新增 import 的符号验证真实存在与签名正确（查定义处或实际 import）
   - 静默吞错：异常吞噬无日志、无注释、无计数痕迹（降级必须可查）
   - vacuous test：挑 2 个最关键测试，回答"故意改坏实现哪一行它才会红"——
     答不出具体行 = 测的是 mock 不是行为
   - 过度工程：单调用方的抽象层、无故障依据的防御分支、"将来可能用"的参数
   - 数据边界：新增上报/外发字段逐个问"为什么需要它"；路径是否相对化；是否泄漏用户环境信息
   - 边界条件：空集 / 极值 / 首条 / 并发首条
   - 异常与资源：泄漏、未清理、finally 缺失
   - 并发异步：竞态、未 await、取消语义
3. findings 按（位置 / 严重度 blocker|suggestion|nit / 说明 / 处置建议）输出
4. 末尾输出你的模型/工具标识，并声明："本评审为独立第二 AI 评审，与开发 AI 不同源；
   仍可能共盲，终裁在责任人"
```

## 三、`self-review.md`（AI 生成，你签字）

```markdown
# 自评审记录：<功能名>

- 责任人：
- 状态：草案
- 确认日期：
- 确认意见：（可选）
- 评审 AI：<标识，须与主力开发 AI 不同>
- 开发 AI：<标识>

> 记录档：签认一次，后续追加评审记录不触发重签。

## <YYYY-MM-DD> 评审结论：通过

- 轮次：N 轮（每轮 = 评审 + 修复 + 复审）
- blocker 处置：<逐条：finding → 已修复，验证命令与结果>
- 未修项（次要问题，责任人拍板不修）：
  - <位置 | 说明 | 不修理由>（各一句话）
```

## 四、FAQ

**Q1：哪里找"不同的 AI"？** 不同工具（如主力 CodeBuddy，另一个用别的工具）或同工具不同模型均可；须运行在**能访问本仓库文件**的环境中（IDE 内另开会话即可），纯对话、无文件访问的 AI 只能做辅助参考，不构成完成双 AI 评审。在 self-review.md 里如实记录标识即可，不做技术验证。

**Q2：哪些可以不修？** blocker（错误行为、上游越权、幻觉 API、测试无效、吞错不可查）必须修；suggestion（更优写法）、nit（风格）由你拍板，不修就在报告里留一行理由。判断口径一句话：**"不修它，功能会错或升级会炸吗？"——不会，就可不修。**

**Q3：可以不做双 AI 吗？** 不可（标准管线强制）——这是压缩 AI 共盲的核心手段；确无第二 AI 可用时，在 self-review.md 中如实记录原因，并人工过一遍 §二 模板第 2 条检查代替。

**Q4：微改动（§6 豁免）要做什么？** 用同一模板的裁剪版：**去掉** design/test-plan 读取与 R2 比对（微改动不碰上游），**只保留**幻觉 API、静默吞错、边界/异常/并发四类检查。结论贴 PR 描述（含两个 AI 标识与未修项），免 self-review.md 文档。
