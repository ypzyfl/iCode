# 需求：豁免治理（R13——豁免须理由与批准）

> 活文档：随时更新、不签认（git 留痕）；意图确认由 design 签认承载。

## 背景与问题

ADR-0013 裁决确认价值取向"豁免机制是升级摩擦的永久来源"，但仅覆盖架构豁免一类。其余豁免面——ruff 豁免（noqa / per-file-ignores 新条目）、测试豁免（skip/xfail/deselect）、CI 门禁跳过、约束例外——此前零管控：lint/测试红时执行者（含 AI）可自行加豁免绕过，坏写法与坏实现借此合法化。豁免事实上是绕过设计约束的后门，有两条扩散路径：有意偷懒（修不过就豁免）与无意模仿（后来者抄存量裸先例）。

局部实践已有先例：ruff-test-exemptions 批次（PR #71）以 design 留痕（组级 vs 规则级取舍标准可审计）+ R2 报批管住了单次豁免决策，但该过程是批次自觉，非普适规则。

## 目标与非目标

- 目标：新增规范 R13「豁免须理由与批准」——封闭枚举定义豁免、默认立场（设计后备而非实现选项）、责任人批准停等点（AI 不得自行添加）、理由留痕（就地注释 + PR 变更导览清单）。
- 非目标：不建集中豁免登记表（登记表本身又是一个"机制"，与 ADR-0013 最小足迹取向冲突）；不做工具化盘点（后续增强，另行立项）；不溯及存量豁免；不覆盖流程豁免（§4.2 免判定清单扩项 / §6 微改动判定——归 ADR-0012 与责任人判定权既有管控）。

## 用户场景

1. AI 实施中遇 lint/测试红：先按规则修（默认立场）；确需豁免 → 呈报三要素（形态 / 逐条理由 / 已尝试的正当路径）→ 责任人批准 → 落地时就地一行理由注释 + PR 变更导览列明。
2. 后来者遇到同类约束挡路：看到的是"经批准的个案 + 为什么"（理由注释），不是裸先例——模仿前先过判断。
3. 评审人 / 评审 AI 打开 PR：变更导览含新增豁免清单，逐条过目裁决。
