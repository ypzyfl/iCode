## 方案概述

新增规范 R13 + 决策档 ADR-0014 + 八处联动改写。核心防线四点：①封闭枚举定义豁免（防规则自身变判断负担，对齐修订元规则）；②默认立场——豁免是穷尽正当路径后的设计后备，不是实现选项（附判据正反例）；③停等点——新增豁免须责任人批准、AI 不得自行添加；④留痕——就地"理由 + 批准指向"注释（git 可查的授权凭据，防先例模仿）+ PR 变更导览豁免清单（§7，评审逐条过目）。审批落点取 PR 轻量裁决（复用现有 PR/评审载体，零新增机制）；档位分级复用 R2/ADR 既有链条，不新增登记形态。

### R13 条文全文（将插入 DEVELOPMENT.md R12 之后；2026-10-30 评审修订版）

> **R13 豁免须理由与批准**：豁免 = 对既有规则/门禁/约束的**个案性绕过**，封闭枚举：①架构豁免通道登记（DAG allowlist 类——现无通道，重建须 ADR+签认，见 R9 例外条款与 `DIRECTORY.md §3`；前瞻条款，通道不存在时永不触发）；②ruff 豁免新增（行内/文件级 noqa、pyproject per-file-ignores 新条目）；③测试豁免新增（skip/skipif/xfail 标记、deselect/路径排除、CI 分片排除）；④CI 门禁跳过（aixcoding 自有 workflow 内弱化门禁的动作：`if:` 条件禁用、continue-on-error、注释 job/步骤、门禁命令收窄如 --exclude；上游 CI 文件改动另触发 R2/R5）。枚举外新豁免形态——含 DIRECTORY.md 明文约束的个案例外，其正道是出 ADR 修规范本身而非留个案豁免——由责任人裁决入列。流程豁免（§4.2 免判定清单扩项、§6 微改动判定）不在此列，各归 ADR-0012 与责任人判定权既有管控。**默认立场：豁免是穷尽正当路径后的设计后备，不是实现选项**——约束挡路先按规则做（修代码/改写法/挪档/正确落位），确不可行才提议豁免。判据对照：正当后备如 RUF001 豁免定制测试的中文断言（规则与场景结构性冲突）；不正当如未查根因即 skip 偶发红测试（仅因不方便）。**新增豁免须责任人批准，AI 不得自行添加**（含修 lint/测试红时顺手加豁免——最高频偷懒路径）；呈报三要素：豁免形态、逐条理由（为何规则不适于此处，而非仅仅不方便）、已尝试的正当路径。留痕（注释是 git 可查的**授权凭据**，不是仅解释——PR body 可变非 git 对象，ADR-0012 同判）：豁免旁就地一行注释含**理由 + 批准指向**（PR 编号或批次 design/ADR），并列入 PR 变更导览"新增豁免清单"（§7）、评审逐条过目。档位分级（复用既有链条）：落上游文件的豁免叠加 R2；架构豁免通道重建叠加 ADR。存量豁免不溯及；工具化盘点（noqa/skip 清单增量进 CI 报告）为后续增强。决策理由见 ADR-0014。

## 备选方案对比

| 方案 | 优点 | 缺点 | 升级冲突面（R1） | 结论 |
|---|---|---|---|---|
| **A. R13 普适规则 + PR 轻量裁决**（呈报批准 + 就地注释 + PR 清单 + 评审过目） | 零新增机制，复用 PR/评审载体；停等点堵 AI 偷懒路径；注释含批准指向 = git 可查授权凭据；理由注释防先例模仿 | 依赖评审人执行力（无机器强制） | 0 上游文件（纯文档批次） | **采用** |
| B. 逐条独立重型审批 | 最严 | noqa 级豁免逐条停等成本不成比例 | 同上 | 否 |
| C. 集中豁免登记表 | 集中可查、可盘点 | 登记表本身又是一个"机制"（ADR-0013 最小足迹取向冲突）；ADR-0012 理由节 3 已否决同构的"exemptions/ 登记文件"（过度设计——防的风险已被源头覆盖）；持续维护负担 | 同上 | 否（工具化盘点列为后续增强） |
| D. 纯机器化（CI 扫豁免增量报告） | 符合修订元规则"交给机器"方向 | 机器不能判断理由是否成立（ADR-0012 同判：豁免本质是人的判断，机器替代要么误伤要么可绕）；实现成本前置阻塞防线建立 | 同上 | 否（规则先行、机器跟进） |

与局部先例的关系：ruff-test-exemptions（PR #71）的单次豁免决策已实践"取舍标准可审计留痕"（组级 vs 规则级边界标准、扩展面代价论证），R13 是该实践的普适化——每类豁免、每次新增都走同等决策过程；该批次的 pyproject 目录行即"存量豁免不溯及"的实例（已有完整 design 留痕）。

## 风险与最坏情况

- **残余风险（签认即明示接受）**：最高频偷懒路径（实施中途 AI 顺手加 noqa/skip）发生在 design 已签、责任人不在场时，"责任人批准"停等点失灵；当前防线 = 评审人过目豁免清单 + 就地注释凭据（事后可查、不可事前拦）——与 ADR-0012"追责优先于机器门禁"同取向；工具化盘点（后续增强）落地前无机器兜底；
- 执行依赖人（评审人过目豁免清单）而非机器强制——缓解：两个 HOWTO 摘要内嵌 R13（评审 AI 即时用新规则）；工具化盘点列为后续增强；
- 误伤正当豁免（拖慢）：呈报三要素轻量、PR 内裁决零文档负担；
- 回滚：删 R13 条款、ADR-0014 标记被取代即回滚，零代码影响。

## ADR 判定

1. 被认真考虑但否决的备选？——**是**（B/C/D 对比，审批落点是明确取舍）；
2. 撤销代价高？——否（删条款即回滚）；
3. 约束未来工作模式？——是（新增停等点），该约束即本批目的，决策档随 ADR-0014；
4. 依赖上游非公开接口或行为？——否。

结论：出 ADR-0014（`standards/adr/0014-豁免须理由与批准.md`）。
