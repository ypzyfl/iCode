## 2. 桌面端如何识别"这是 iCode"

**唯一开关是 ACP `initialize` 响应里的 `agentInfo.name === 'iCode'`**（`packages/adapters-node/src/agent-host/acp-agent-host.ts:4584-4586` 的 `isChrysConnection`；`agentName` 取自 initialize 的 `agentInfo.name`，约 :1787）。

⇒ iCode 契约：**ACP initialize 的 `agentInfo.name` 必须保持字面量 `'iCode'`**，改名会直接断掉桌面端全部 iCode 专属分支。

## 3. 模型目录（模型列表来源——不从 iCode 拿）

- 接口：`POST {businessBackendOrigin}/csas/web/model/myModelList`，header `token: <账户 access token>`，body `{}`（`apps/desktop/src/main/account-model-catalog.ts:14,66-76`）。
- 响应记录给出 `modelKey`、`displayName`、`supportsVision`、`contextLength` 等。
- 拉取时机：运行时创建时（`apps/desktop/src/main/index.ts:1160-1166`），登录后可 `refreshModels` 刷新（index.ts:555-593）。
- 后端不可达时 fallback：app-config.json 的 `model.modelId` 单模型目录（index.ts:1163）。
- 渲染进程下拉列表 = `shell.bootstrap?.models?.items`（`apps/desktop/src/renderer/src/stores/session-composer-store.ts:419`）。

⇒ **模型列表永远不流经 iCode**；iCode 不需要提供"模型列表查询"能力。

## 4. 模型物化为 iCode 模型 profile（文件通道）

`apps/desktop/src/main/chrys-model-profile.ts::prepareChrysModelProfiles`（约 :74-161）：

- 落盘位置：`<account-private>/chrys-home/<配置目录名>/models/<profileId>.yaml`。
  - 配置目录名按平台对齐 iCode 的解析（`chrysConfigDirectoryName`，约 :53-56）：**Windows 是 `chrys`**（iCode 硬编码 `%APPDATA%\chrys`，桌面端把 `APPDATA` 指向 `chrys-home`），**POSIX 是 `.chrys`**（iCode 用 `~/.chrys`，桌面端把 `HOME` 指向 `chrys-home`）。两端解析代码互为镜像。
- profile 内容（JSON 序列化写进 `.yaml`——JSON 是 YAML 子集，iCode 的 YAML loader 可直接解析）：
  ```json
  { "id": "<profileId>", "name": "<displayName>", "provider": "openai",
    "api_style": "chat_completions", "model_id": "<modelKey>",
    "max_context_tokens": <contextLength ?? 128000>, "base_url": "<app-config 提供>",
    "api_key": "", "stream": true, "vision": <supportsVision> }
  ```
  字段与 iCode `ModelProfile` schema（`src/chrys/service/profiles/models/schema.py`）一一对应，未写字段吃默认值（`max_output_tokens` 等）。
- **`api_key` 刻意留空**：凭据只走 env（token 通道，§6），文件里不含密钥。
- provider 映射（:24-28）：`AIxCoding → openai`（`defaultBaseUrl: null`，必须由 app-config 给 base_url，否则报错）；`openai → openai`；`deepseek → deepseek-openai`。
- profileId 规则（`chrysModelProfileId`，:36-41）：modelKey 能安全当文件名（`[A-Za-z0-9][A-Za-z0-9._-]{0,127}` 且非 `.`/`..`）就原样用；否则 `aixcoding-<sha256 前 24 hex>`。桌面端两侧（发协议、写文件）用同一纯函数。
- 目录安全检查：账号私有目录、拒绝符号链接、POSIX 要求 0700、目录最多 128 个 profile。
- `capabilityModelProfileId`（:60-65 + 末尾挑选逻辑）：优先选**支持 vision** 的模型（没有才用 default）——它经 `CHRYS_MODEL_PROFILE` env 传给 iCode 作**启动默认 profile**，因为 iCode 在 `initialize` 时就冻结 `promptCapabilities.image`，启动 profile 不支持视觉会导致视觉会话也被拒。**它不是用户选的模型。**

## 5. 选中模型的传递（协议通道）

- `session/new` 参数只有 `{ cwd, mcpServers: [] }`，**不带模型**（`acp-agent-host.ts:753-757`）。
- `session/new` 成功后立即 `#applyModelId`（:789-799 → :1953-1978）：对 iCode **跳过** `session/set_config_option`，只发 `session/set_model`，参数 `{ sessionId, modelId }`，modelId 为**裸 profile id**（`provider/` 前缀被剥掉；候选列表见 `#requestNativeModel` :1554-1581）。
- **set_model 失败 = 会话创建失败**（错误文案 "The Agent session was created, but its selected model could not be confirmed"，:794-798）——iCode 找不到 profile 必须报错，不能静默成功。
- 会话中切模型：公开方法 `setModel`（:1509-1544）走同一 `session/set_model`；IPC `session.setModel`（`apps/desktop/src/shared/desktop-api.ts:1211`）。
- 桌面端内部 modelId 形如 `provider/<profileId>`（`apps/desktop/src/main/desktop-runtime-service.ts:3873-3885` 的 `#modelId`；agent 是 `agent:icode` 时 id 段取 `chrysModelProfileId(selected)`），进入 ACP 层后再剥成裸 id。

## 6. Token 通道（参照系：模型凭据怎么来）

- 每 provider 一个 env 名（`apps/desktop/src/main/desktop-agent-connection-service.ts:31-41`）：`AIxCoding → OPENAI_API_KEY`、`openai → OPENAI_API_KEY`、`anthropic → ANTHROPIC_API_KEY`、`deepseek → DEEPSEEK_API_KEY` 等。
- 凭据来源优先级：`credentials.json` 文件 > protected store > 默认值（:278-345）。
- 注入点：runtime-composition 里 iCode 连接工厂的 `environment` 块（`runtime-composition.ts:2140-2157`），随子进程 spawn 传入。**与登录 token 的关系**：AIxCoding 提供方下这就是登录 token（fix-1008 构建已如此，iCode 委托登录的兼容通道 `AIXCODING_USER_EHR`+`OPENAI_API_KEY` 即为此设计）。
- **用户 EHR 的投递路径（2026-10-09 补查）**：`AIXCODING_USER_EHR` 由 `userContextEnvironment`（runtime-composition.ts:798-801，取 `accountScope.profile.ehr`）并入 `trustedPiDefaults.environment`（:855-866），再随 `connection.value.environment` 进入 iCode 子进程。**三条凭据路径只有两条带上它**：credentials.json 路径（connection-service:288-292 展开 defaults env）和"无存储连接"默认路径（:303-306 直接用 defaults env）会带；**protected-store 凭据路径（:330-338）的 env 从零构建、丢弃 defaults**——该路径下 iCode 子进程收不到 EHR（token 不受影响，provider 变量单独写入）。另注意 iCode ACP 模式当前没有 `AIXCODING_USER_EHR` 的消费方（只有 TUI `/login` 接线），变量缺席不构成故障。

## 7. iCode 子进程拉起全景

- 启动参数（`apps/desktop/resources/config/app-config.json:47-60`）：`icode.args = ["acp", "--agent", "Code", "--approval", "manual"]`；二进制 `resources/icode/chrys.exe`（win）等。
- `resolveIcodeLaunch`（`index.ts:1538-1567`）解析固定路径二进制，缺失即禁用 iCode runner。
- `chrysAcpArgs`（`chrys-agent-profile.ts:633-648`）：把 `--agent` 的值替换成生成的 `aixcoding-<sha256-16>` 档案名（无则追加 `--agent <name>`）。
- `--approval manual` 只是兜底基线：**每会话用 `session/set_mode` 重申生效模式**（`acp-agent-host.ts:805-818`；模式映射 `runtime-composition.ts:220-222`）。
- env overlay（`runtime-composition.ts:2140-2157`，spawn 于 `packages/adapters-node/src/agent-host/stdio-acp-connection.ts:207-216`）：
  ```
  继承白名单 env（HOME, LANG, LC_ALL, PATH, PATHEXT, SHELL, SystemRoot, TEMP, TMP, TMPDIR,
                  USERPROFILE, WINDIR, XDG_CONFIG_HOME —— stdio-acp-connection.ts:11-25）
  + icodeLaunch.environment
  + connection.value.environment        # token：OPENAI_API_KEY 等
  + HOME=<account-private>/chrys-home
  + (win32) APPDATA=<account-private>/chrys-home
  + CHRYS_MODEL_PROFILE=<capabilityModelProfileId>   # 能力协商 profile，非用户选择
  + (runtime ready) PYAPP_INSTALL_DIR_CHRYS=<预热目录>
  ```
  spawn 选项：`windowsHide: true`，非 Windows `detached: true`。
