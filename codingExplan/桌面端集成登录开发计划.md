## 3. M3 — 桌面端主通道变量（桌面端仓库；**可选加固，非阻塞**）

先说结论：**不改桌面端，集成今天就能工作**。现有 fix-1008 构建已把登录 token 以 `OPENAI_API_KEY` 注入并伴随 `AIXCODING_USER_EHR`，iCode 的兼容通道（§1.1 / 方案 §4）就是为这一对变量设计的。本节只是把"模型凭证变量恰好也是账户 token"这个隐式复用升级为显式契约——何时做、甚至不做，都不影响功能；动机（语义歧义、提供方变量名耦合、误判窗口）见方案 §4 末段。

改动点：`apps/desktop/src/main/runtime-composition.ts` icode 连接工厂的 `environment` 块（约 2136 行注释下方），追加：

```ts
// 与 OPENAI_API_KEY 同值同生命周期：iCode 的登录层把它认作委托账户 token。
CHRYS_AUTH_DELEGATED_TOKEN: requireModelCredential(options.modelCredential),
CHRYS_AUTH_DELEGATED_EHR: profile.ehr,        // 可选（AIXCODING_USER_EHR 已有，可不加）
```

验收：
- 桌面端登录 → 选 iCode 引擎开会话 → 子进程 env 同时含 `CHRYS_AUTH_DELEGATED_TOKEN` 与 `OPENAI_API_KEY`；
- 兼容通道仍保留（iCode 端优先读主通道，旧桌面构建不受影响）。

注意事项（桌面端现状，方案 §2.1）：无 token 刷新、子进程 env 不热更新——**不需要**为此改造：委托 token RAM-only + 拒绝即回落的设计已把这些边界吃掉（方案 §8）。

## 4. M4 — 联合验证清单（双端联调时逐项走查）

环境：内网可达 PROD（`82.187.34.98`），或本地 mock（`CHRYS_AUTH_SERVER_URL` 指到本地 mock 需两端同时指向，通常联调直接打 PROD/DEV）。

**S2 主链路（桌面端选 iCode）**
- [ ] 桌面端登录任意账号 → 设置选 iCode 引擎 → 新会话发消息，模型正常回复（`OPENAI_API_KEY` 链路，改造前即通，回归确认）；
- [ ] 子进程内 `stored_token` 返回桌面端 token（可在 trajectory/日志侧由同事的下游消费验证，或临时探针）；
- [ ] `check_silent` 对委托 token 返回 AccountInfo（ehr 与桌面端登录账号一致）；
- [ ] 桌面端退出登录 → 原会话子进程 `stored_token` 回落（通常为 None，表现为未登录）；重新登录 → 新会话恢复正常；
- [ ] 断网/内网不可达时：会话不受影响（离线保留），恢复后 `check_silent` 通过。

**S1 不受干扰（独立 TUI 回归）**
- [ ] 无桌面端 env 的普通终端：`/login` 设备码流程照常（mock 三步或内网真实流程）；
- [ ] `/logout` 清凭据照常；`stored_token`/`check_silent` 行为与改造前一致；
- [ ] 桌面端 chrys-home（隔离 HOME）里的任何状态不影响真实 `~/.chrys`（`%APPDATA%\chrys`）。

**边缘**
- [ ] 在桌面端注入过 env 的终端里手工起 TUI：`/login`、`/logout` 出托管 toast，不弹对话框、不清凭据；
- [ ] 仅设 `OPENAI_API_KEY`（无 EHR）的独立 shell：不误判委托。

## 5. M5 — 后续增强（未排期，明确不在本次范围）

- **LLM 请求注入**：`service/llm/clients.py::_build_default_headers` 是唯一请求头装配点；如业务要求账户 token 随 LLM 请求上报（区别于 `OPENAI_API_KEY` 模型凭证），再从 `stored_token` 接线。注意这将跨出 `aixcoding/`，需重走方案评审。
- **委托 token 有效期提示**：桌面端将来若在 token 响应里带 `expires_in`，可通过新变量（如 `CHRYS_AUTH_DELEGATED_EXPIRES_AT`）下发，iCode 侧在 `DelegatedCredential` 加可选字段即可，向前兼容。
- **状态栏登录指示**：设计文档 §9 遗留项，与本次无关。

## 6. 风险与回退

| 风险 | 缓解 |
|---|---|
| 兼容通道误判（独立 shell 同时导出 EHR + OpenAI key） | 后果止于"短暂显示已登录→校验失败回落未登录"，无本地破坏；M3 落地后消除 |
| 桌面端 `modelCredential` 语义将来与账户 token 分离 | 主通道变量是独立命名契约，届时桌面端只改注入值，iCode 端零改动 |
| 回退 | iCode 侧改动集中在 `aixcoding/auth/delegation.py` + `session.py` 委托分支 + `screen.py` 两处提示；revert 这三个文件即回到改造前，测试同步 revert 两个文件即可 |
