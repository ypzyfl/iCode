## 1. 项目身份

| 项 | 值 |
|---|---|
| 对外名称 | **iCode**（命令 `icode`） |
| 包名 | `chrys`（`src/chrys/`，配置目录 `~/.chrys` / `%APPDATA%\chrys`，环境变量 `CHRYS_*`） |
| 版本 | `0.29.0`（`pyproject.toml` 是版本与依赖的唯一事实源） |
| 解释器 | **Python 3.14+**（PEP 758 无括号多异常等新语法，勿用 3.13 导入源码） |
| 形态 | Textual TUI（主入口）+ headless CLI + ACP stdio 服务器 |
| 配置/依赖 | `pyproject.toml` + `uv.lock`（全量精确 pin）；工具一律 `uv run` |

一句话：一个 agent 平台——LLM 内核（kernel）+ 工具/会话/配置服务层（service）+ 编排（orchestration）+ 三种前端（app：TUI/CLI/ACP）。

## 3. 主包 `src/chrys/` —— 五层架构

分层 DAG（`tests/architecture/test_layering.py` 强制，禁止反向导入）：
`app(4) → orchestration(3) → service(2) → kernel(1) → foundation(0)`

| 层 | 目录 | 职责与关键文件 |
|---|---|---|
| **foundation** (0) | `foundation/` | 无依赖的通用原语：`config/`（Settings 分层配置）、`events/bus.py`（EventBus，前后端唯一通道）、`models/`（turns/history 标记）、`i18n/`（msg + 编译好的 catalog）、`platform/`（进程/文件/剪贴板）、`trajectory/`（运行轨迹）、`errors/`（错误分类）、`text/` |
| **kernel** (1) | `kernel/` | LLM 循环内核，扁平无子包：`loop.py`（turn 主循环、echo 移除、finalize）、`client.py`（存储模式解析）、`exchanges.py`（调用↔结果配对语法）、`compaction.py`（上下文压缩）、`tools/`、`middleware/`；`_*.py` 为私有模块 |
| **service** (2) | `service/` | 业务服务：`llm/`（三家 wire 协议包 chat_completions / openai_responses / anthropic_messages + wire_client）、`profiles/`（agent/model YAML）、`tools/builtins/`（内置工具含 web）、`mcp/`、`skills/`、`hooks/`、`approval/`、`session/`（持久化）、`context/compaction/`、`agent_middleware/`（system reminder）、`workflows/`（SDK/graph/scheduler/worker） |
| **orchestration** (3) | `orchestration/` | 引擎与编排：`startup.py`（bootstrap_runtime，所有入口必经）、`engine/`（assembly/build/run/state，AgentEngine）、`invoker/`（统一调用契约）、`sub_agents/`、`workflows/`、`session_host.py`（每 run/session 一个总线+引擎+会话） |
| **app** (4) | `app/` | 前端：`cli/app.py`（argv[0] 手写 if 分发，未匹配落 TUI）、`tui/`（screens/main 主屏、widgets/chat 聊天区、behaviors、terminal 终端仿真）、`acp/`（JSON-RPC 服务器，日志走 stderr）、`features/` |
| 门面 | `workflows.py` | service 层 workflows 的 re-export |

另有两个特殊运行环境：`service/workflows/sdk/` 与 `worker_host.py` 跑在用户解释器里，**stdlib-only + Python 3.9 语法**（不得现代化改写）。

## 4. 入口与日常命令

```bash
uv sync --extra all                                # 环境安装（裸 uv sync 会卸载 extras）
uv run icode                                       # TUI 主入口（= chrys）
uv run icode run "<prompt>" -a Code                # headless（审批 BYPASS）
uv run icode acp                                   # ACP stdio 服务器
uv run icode serve|agents|models|workflow|trajectory|install

uv run python scripts/chrys_test.py --smart --paths <改动文件...>   # 默认验证
uv run ruff check src/ tests/ scripts/chrys_test.py ...            # lint（fix=true 会改文件）
uv run ruff format --check ...                     # 格式
uv run ty check --error-on-warning --python-platform linux src/chrys  # 类型（×3 平台）

uv run python scripts/i18n.py extract|update|translate|compile|check  # i18n 流水线
```

规则要点：验证用 Smart Test 传 `--paths`；测试默认拦截非 loopback 出网；用户可见改动须同步更新 `docs/en` 与 `docs/zh-Hans`；提交 `--no-verify` + 显式路径，禁止 `git add -A`。详见 `AGENTS.md`。

## 5. `aixcoding/` —— 登录改造增量模块（本次分支的主体）

OAuth2 设备码登录（AIxCoding 企业账号），与 `src/chrys` **物理隔离**以便评审；`src/chrys` 只做最小接线。

```
aixcoding/
├── README.md               # 目录约定、与架构测试的边界（不受分层 DAG 约束）
├── __init__.py             # 包说明（版本 0.1.0）
├── auth/                   # 协议客户端 + 凭据存储 + OS 级加密（公共 API 从这里 import）
│   ├── types.py            # Environment(local/dev/prod)、DeviceCode、TokenResult、
│   │                       #   AccountInfo、StoredCredential；TTL=365 天
│   ├── errors.py           # AuthError 家族：Network/Server/Denied/Timeout/Cancelled/ProtectUnavailable
│   ├── environments.py     # 三档地址常量表；CHRYS_AUTH_ENVIRONMENT / CHRYS_AUTH_SERVER_URL 解析
│   ├── client.py           # AuthClient：device/code → device/token 轮询 → user/info
│   │                       #   （信封解析：前两个读 result、user/info 读 data；不看 HTTP 状态码）
│   ├── crypto.py           # ProtectBackend：Windows DPAPI / macOS Keychain / Linux 明文降级 /
│   │                       #   Memory 兜底；entropy 标签 aixcoding-account-auth；get_backend() 探测降级
│   ├── storage.py          # CredentialStore：<config_dir>/users/<env>/current 明文指针
│   │                       #   + private/secrets/<32hex>.json 密文信封（原子写、sha256 校验、O_NOFOLLOW）
│   └── session.py          # LoginSession（check_silent / request_device_code /
│                           #   complete_login / logout）+ get_login_session() 进程单例
└── tui/
    ├── login.py            # LoginDialog（Textual 对话框）：展示用户码 → 自动开浏览器 →
    │                       #   轮询成功 dismiss(account)，取消/失败显示错误；Esc/取消置 cancel_event
    └── login.tcss          # 对话框样式
```

对 `src/chrys` 的接线（仅 3 个文件，共约 108 行）：

| 文件 | 改动 |
|---|---|
| `app/tui/screens/main/commands.py` | 注册 `/login`、`/logout` 斜杠命令 + man 帮助页（i18n） |
| `app/tui/screens/main/screen.py` | `_open_login_dialog`（推入 LoginDialog，成功 toast「已登录：xx」）与 `_perform_logout`（toast） |
| `app/tui/app.py` | `on_mount` 末尾挂 `_silent_login_check` 后台任务（静默校验/自清理凭据，一切异常吞掉，不打扰启动）；`on_unmount` 取消 |

测试在 `tests/app/aixcoding/`（7 个测试文件 + conftest）。

## 6. `mock_server/aixcoding_auth/server.py` —— 本地 mock 登录服务

内网认证服务（PROD `82.187.34.98` / DEV `81.89.182.150`）外网不可达，外网开发全靠它。标准库实现，零依赖，端口 `127.0.0.1:7777`。

- 路由：`POST /api/v1/auth/device/code`、`POST /api/v1/auth/device/token`、`POST /api/v1/user/info`、`GET /device/verify`（本地授权确认页，manual 模式）
- **响应信封逐字节对齐真实服务**（含怪癖）：pending 时 `success` 仍为 `true`、`user/info` 用 `data` 而非 `result`、token 错误时无 `success` 键且 HTTP 恒 200
- 模式：`manual`（默认，等用户在授权页点确认）/ `auto`（奇偶交替，冒烟用）；`--deny`、`--slow-down N` 验证失败分支
- 可导入复用：`MockAuthConfig` / `MockAuthState` / `create_server`（测试起 loopback 桩）

```bash
uv run python mock_server/aixcoding_auth/server.py                 # 启动（manual 模式）
CHRYS_AUTH_ENVIRONMENT=local uv run icode          # 客户端指向它
```
