## 1. 环境准备

### 1.0 Shell 与目录约定（先读，避免白跑一趟）

- **所有命令默认在 cmd、项目根 `D:\project\iCode` 下执行**。`uv run` 依赖当前目录的 `pyproject.toml`，在其它目录（如 `C:\Users\lhc`）运行会报 `error: Failed to spawn: icode`。
- **PowerShell 用户注意**：`set CHRYS_AUTH_ENVIRONMENT=local` 在 PowerShell 里是 `Set-Variable` 的别名调用，**不会设置进程环境变量、也不报错**——iCode 会静默以默认 `prod` 档启动。PowerShell 必须写 `$env:CHRYS_AUTH_ENVIRONMENT = "local"`。
- 常用环境变量对照（设完后在**同一窗口**启动 iCode）：

| 变量 | cmd | PowerShell |
|---|---|---|
| `CHRYS_AUTH_ENVIRONMENT=local` | `set "CHRYS_AUTH_ENVIRONMENT=local"` | `$env:CHRYS_AUTH_ENVIRONMENT = "local"` |
| `PYTHONPATH=项目根`（`/login` 必需，原因见 §2.1） | `set "PYTHONPATH=%CD%"` | `$env:PYTHONPATH = "$PWD"` |

> cmd 的 `set X=值 && 下一条` 会把值后面的尾随空格一并存进变量——本项目代码已对变量值 `.strip()`，实测不受影响，但推荐引号写法 `set "X=值"`。

### 1.1 依赖安装

项目要求 Python 3.14+（uv 自动管理解释器，无需手工安装）。


## 2. 项目启动：本地（mock）与生产

登录环境由环境变量 **`CHRYS_AUTH_ENVIRONMENT`** 选择：`local` / `dev` / `prod`，未知值回落 `prod`，**不设置时默认 `prod`**。它在**进程启动时**解析——改完环境变量必须重启 iCode，会话内改不生效。另有 `CHRYS_AUTH_SERVER_URL` 可覆盖两个认证服务的 protocol+host（保留 `/csas` 与 `/aicoding` path 前缀；非法值被忽略）。

### 2.1 本地环境（对接 mock，外网开发）

两个终端，均在项目根 `D:\project\iCode`：

```cmd
:: 终端 1：先起 mock 登录服务（见 §4）
uv run python mock_server/aixcoding_auth/server.py

:: 终端 2：切到 local 档 + 把项目根挂进 PYTHONPATH（/login 必需，见下方说明），再启动 iCode
set "CHRYS_AUTH_ENVIRONMENT=local"
set "PYTHONPATH=%CD%"
uv run icode
```

PowerShell 等价（终端 2）：

```powershell
$env:CHRYS_AUTH_ENVIRONMENT = "local"
$env:PYTHONPATH = "$PWD"
uv run icode
```

> ⚠️ **`/login` 当前必须设 `PYTHONPATH`（已知缺陷，2026-10-08 实测）**：`aixcoding/` 只是仓库根的源码目录，**没有安装进 `.venv`**（`pyproject.toml` 的 wheel `packages` 只含 `src/chrys`）；而 `uv run icode` 走 entry point（`.venv\Scripts\icode.exe`），sys.path 只有 Scripts 与 site-packages，**不含项目根**——进 TUI 后执行 `/login` 会红屏：
>
> ```
> ModuleNotFoundError: No module named 'aixcoding'
> ```
>
> 临时解法就是上面的 `PYTHONPATH`。对照：`uv run python verify_login.py`（§5.2）与 `uv run python verify_login_dialog.py` **不需要** PYTHONPATH——Python 会把脚本所在目录（= 项目根）放进 sys.path[0]，entry point 没有这个行为。不碰 `/login`、`/logout` 时**无需设置**：启动的静默登录检查对异常整体吞掉，普通对话完全不受影响。
>
> **根治方向（待做，需单独决策）**：把 `aixcoding` 加进 `pyproject.toml` 的 `[tool.hatch.build.targets.wheel] packages`（`["src/chrys", "aixcoding"]`）后 `uv sync --extra all`。这一步同时修好 `uv run icode` 与发布 wheel——当前 wheel 里也没有 `aixcoding`，打包产物上的 `/login` 会同样崩。

### 2.2 生产环境（行内内网）

生产是**默认档**，不做任何配置直接启动即可：

```cmd
uv run icode
```

要点：

- 登录目标 auth `http://82.187.34.98/csas/api/v1`、data `http://82.187.34.98/aicoding/api/v1`，**要求机器在行内内网（或 VPN 可达）**；外网机器上 `/login` 会停在「无法获取登录码」；
- 进 TUI 前建议先验活（通则再登录）：

```cmd
curl -X POST http://82.187.34.98/csas/api/v1/auth/device/code -H "Content-Type: application/json" -d "{\"client_id\":78}"
```

- 凭据按环境隔离，prod 档存 `%APPDATA%\chrys\users\prod\`（与 `users\local\`、`users\dev\` 互不干扰，见 §6）；
- 显式指定等价：`set CHRYS_AUTH_ENVIRONMENT=prod`；临时换指向：`set CHRYS_AUTH_SERVER_URL=82.187.34.98`（或带端口）——备用内网地址 `22.189.54.139` 就是这样切，无需改代码；
- 认证请求 `trust_env=False`（`aixcoding/auth/client.py`）：**不走系统/环境代理**。开了 HTTP(S)_PROXY 本地代理也不会劫持登录流量（本地代理答 502 明文会被误判成服务端错误、静默清凭据），内网直连即预期行为；
- **当前发布包里没有 `aixcoding`**（wheel 打包只含 `src/chrys`）——生产机上 `/login`、`/logout` 目前不可用，需先落地 §2.1 所述打包修复；普通对话不受影响。

```cmd

```

其它子命令：`icode acp`（ACP 服务器）、`icode agents`、`icode models`、`icode workflow` 等。

### 5.1 登录对话框（TUI）验证 —— /login 命令（推荐）

```cmd
:: 终端 1：启动 mock（manual 模式，默认 127.0.0.1:7777）
uv run python mock_server/aixcoding_auth/server.py

:: 终端 2：切到 local 档 + 挂 PYTHONPATH（/login 必需，原因见 §2.1），启动 iCode
```

在 iCode 输入框输入 `/login` 回车：弹出"AIxCoding 登录"对话框 → 显示用户码（如 `ABCD-EFGH`）并自动打开浏览器验证页 → 在浏览器点 *Confirm authorization* → 对话框自动关闭 + toast「已登录：大熊猫」。

**可验证分支**：

| 操作 | 预期 |
|---|---|
| 对话框内按 `Esc` 或点"取消" | 对话框关闭，不存储任何凭据 |
| 终端 1 不启动 mock，直接 `/login` | 对话框显示"无法获取登录码，请稍后重试" |
| 验证页点 *Deny* | 对话框显示"登录未完成" |
| `/logout`（已登录） | toast「已退出登录」，`%APPDATA%\chrys\users\local\` 下的指针与信封被删除 |
| `/logout`（未登录） | toast「尚未登录」（警告样式），无其它动作 |
| 已登录状态下重启 iCode | 启动无任何提示（静默校验通过），凭据继续可用 |
| 篡改信封后重启 iCode | 静默校验自动清理死凭据（无提示），下次 `/login` 干净开始 |
| `/man login`、`/man logout` | 显示双语帮助页 |
| 不设 `PYTHONPATH` 直接 `/login` | 红屏 `ModuleNotFoundError: No module named 'aixcoding'`（已知缺陷，见 §2.1） |

凭据落盘检查按 5.3。

**备选**：`uv run python verify_login_dialog.py`（项目根目录的最小宿主脚本，不进 iCode 主界面直接弹同一对话框，效果等同 `/login`，接线前用于验证；接线完成后可删）。

### 5.2 无 UI 全链路脚本验证

前置：终端 1 已启动 mock。将下面保存为**项目根目录**下的 `verify_login.py`（必须放根目录——`uv run python 脚本.py` 会把脚本所在目录放进 sys.path[0]，`aixcoding` 正是靠它解析，放子目录会报 `ModuleNotFoundError`。注意该机制只对"脚本"生效；`uv run icode` 是 entry point、没有该行为，所以 §5.1 需要显式 `PYTHONPATH`，见 §2.1）：

```python
"""人工验证：走完 设备码 -> 浏览器确认 -> token -> 用户信息 -> 落盘 -> 静默检查 全链路。"""
import asyncio
import webbrowser

from aixcoding.auth import LoginSession
from aixcoding.auth.types import Environment


async def main() -> None:
    session = LoginSession(
        environment=Environment.LOCAL,
        endpoints=("http://127.0.0.1:7777/api/v1", "http://127.0.0.1:7777/api/v1"),
    )
    code = await session.request_device_code()
    print("用户码:", code.user_code)
    webbrowser.open(code.verification_uri_complete)  # 打开授权页，手动点 Confirm authorization

    account = await session.complete_login(code)
    print("登录成功:", account.display_name, "/", account.dept_name)
    print("token:", session.stored_token)

    silent = await session.check_silent()  # 模拟下次启动的静默检查
    print("静默检查:", silent.display_name if silent else "None（异常）")

    session.logout()
    print("登出后 token:", session.stored_token)  # 应为 None


asyncio.run(main())
```

运行：`uv run python verify_login.py`（或 `.venv\Scripts\python.exe verify_login.py`；若坚持放其它目录，需先 `set PYTHONPATH=%CD%`）

**预期输出**：用户码形如 `ABCD-EFGH`；浏览器弹出授权页，点 *Confirm authorization* 后脚本继续，打印 `大熊猫 / 上海分中心技术平台研发部`，token 以 `mock-token-` 开头；静默检查返回同一用户；登出后 token 为 `None`。

|---|---|---|

## 6. 登录信息存储详解

### 6.1 存储位置（按 OS）

| OS | 根目录 | 本项目实际路径 |
|---|---|---|
| **Windows** | `%APPDATA%\chrys` | `C:\Users\<用户>\AppData\Roaming\chrys\users\<env>\` |
| **macOS** | `~/.chrys` | `~/.chrys/users/<env>/` |
| **Linux** | `~/.chrys` | `~/.chrys/users/<env>/`（麒麟等信创发行版相同，随用户主目录解析；arm64/x86_64 一致） |

`<env>` 为 `local` / `dev` / `prod`（`CHRYS_AUTH_ENVIRONMENT`，默认 `prod`）——每个环境各存一份凭据，互不干扰。

目录结构：

```
<config_dir>/users/<env>/
├── current                         # 明文指针：secret:v1:<32hex>
└── private/secrets/<32hex>.json    # 加密信封
```

### 6.2 加密方式（按 OS，`aixcoding/auth/crypto.py`）

| OS | 后端 | 说明 |
|---|---|---|
| **Windows** | **DPAPI**（`crypt32.dll` 的 `CryptProtectData`） | 按用户加密，换用户/换机器不可解密；entropy 标签 `aixcoding-account-auth` |
| **macOS** | **Keychain**（`/usr/bin/security` 存 generic-password） | 信封里的 `ciphertext` 只存钥匙串账号指针，真实密文在钥匙串中 |
| **Linux** | **明文降级**（`PlaintextBackend`） | 镜像参考实现 `setUsePlainTextEncryption(true)`；仅靠 0700 目录 / 0600 文件权限保护 |
| 探测失败（无后端可用） | `MemoryBackend`（内存态） | 重启即失，需重新登录；不崩溃 |

### 6.3 存了哪些信息

加密信封（`private/secrets/<id>.json`）：

```json
{
  "schemaVersion": 1,
  "purpose": "account_auth",
  "ciphertext": "<base64 密文>",
  "ciphertextSha256": "<sha256 校验和>"
}
```

信封内**明文 payload**（解密后，`StoredCredential`）：

| 字段 | 内容 |
|---|---|
| `token` | 登录令牌（核心敏感字段） |
| `refresh_token` | 刷新令牌（保留字段，暂不自动刷新） |
| `userId` / `ehr` | 员工号 |
| `environmentId` | `local` / `dev` / `prod` |
| `purpose` | 固定 `account_auth` |
| `expiresAt` | 本地盖章的过期时间（TTL 365 天） |
| `schemaVersion` | 2 |

**不落盘**：`AccountInfo`（ehr、姓名、region、部门、isStWg、userType）只在内存中，每次由 `/user/info` 现查。

安全特性：原子写（temp + `os.replace`）、sha256 完整性校验失败自清理（指针删除→下次干净登录）、POSIX `O_NOFOLLOW` 打开。

### 6.4 如何查看已存储的 token（按 OS，内网排障用）

三个前提，缺一就会读不到：**同一个解释器**（`aixcoding` 装在 icode 运行的那个环境里）、**同一个系统用户**（DPAPI/Keychain 按用户隔离）、**同一套 `CHRYS_AUTH_*` 环境变量**（存储按环境分目录，读错档位等于读另一个库）。

**Linux（含麒麟/信创）——文件直读**。明文降级后端下，信封里的 `ciphertext` 就是 base64(明文 payload JSON)，无需任何代码：

```bash
cat ~/.chrys/users/prod/current                       # secret:v1:<id>，取出 <id>
cat ~/.chrys/users/prod/private/secrets/<id>.json     # 信封（0600）
grep -o '"ciphertext": *"[^"]*"' ~/.chrys/users/prod/private/secrets/<id>.json \
  | cut -d'"' -f4 | base64 -d                          # 解出 payload JSON（含 token/refresh_token）
```

**Windows / macOS——走 API**（密文分别在 DPAPI / 钥匙串里，`cat` 文件看不到明文）。用运行 icode 的同一解释器执行：

```python
# dump_token.py —— 打印凭据并做一次服务端验活
import asyncio
from aixcoding.auth import get_login_session

s = get_login_session()
cred = s.store.load(s.environment)
print("environment:", s.environment.value)
if cred is None:
    print("无已存储凭据（未登录 / 后端降级为内存态 / 环境档位不一致）")
else:
    print("user:", cred.user_id, "/", cred.ehr)
    print("expired:", cred.is_expired, "expires_at:", cred.expires_at)
    print("token:", cred.token)
    print("refresh_token:", cred.refresh_token)
print("服务端校验:", asyncio.run(s.check_silent()) or "无效或不可达")
```

补充说明：

- `check_silent()` 的语义：网络不通**不清**凭据（离线≠登出）；服务端明确拒绝（用户不存在等）会**自清理**，此后 `stored_token` 为 `None`。
- 加密后端探测失败时降级 `MemoryBackend`：凭据只在内存，磁盘上什么都没有，重启需重新登录。
- macOS 的密文实际存放在钥匙串（服务名 `aixcoding-account-auth`），信封里的 `ciphertext` 只是钥匙串账号指针——也可用「钥匙串访问」工具按服务名检索。
